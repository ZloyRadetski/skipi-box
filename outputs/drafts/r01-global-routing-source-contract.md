# R01 — Global routing source contract and test-first slices

Read-only source and history audit, 23 October 2026. This records the Android legacy global-routing implementation and separates its component-level semantics from the currently reachable application flow. The global `RoutingPage` has no active entrypoint in this checkout and was not reachable in the inspected history. This draft does not propose adding global UI or navigation.

## Keep global and profile routing separate

The Android global-routing component edits `AppState.routeRules`, `routeDomainStrategy`, `defaultRouteOutboundTag`, and `nextRouteRuleId` ([`AppState`](../../app/src/main/kotlin/app/AppState.kt:154), with `nextRouteRuleId` defaulting to 10 at [line 157](../../app/src/main/kotlin/app/AppState.kt:157)). These component behaviors are preserved below as source semantics. [`RoutingPage`](../../app/src/main/kotlin/features/routing/RoutingPage.kt:101) is not mounted by the active app navigation, so these details do not describe a currently reachable user flow. The common [`RoutingConfigRecord`](../../shared/app/src/commonMain/kotlin/app/skipi/app/model/PersistedModels.kt:187) carries strategy, default outbound, and rules, but omits the ID counter.

P04’s “Routing → Rules” is a separate traffic-profile editor over `ShadowrocketRule` and profile `.conf` content ([profile Routing section](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigRoutingSectionScreen.kt:27), [profile rule editor](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigRuleEditorPage.kt:31)). Its save/controller semantics and tests do not cover Android’s global `RouteRule` list, global default outbound, or app-wide domain strategy.

## Defaults, persistence, and current navigation entrypoints

- **There are no platform-specific seed rules today.** Android defines `DefaultRouteRules` as `emptyList()` ([defaults](../../app/src/main/kotlin/app/AppStateDefaults.kt:32)); `AppState.routeRules` uses it and starts `nextRouteRuleId` at 10 ([state defaults](../../app/src/main/kotlin/app/AppState.kt:154)). Desktop `DesktopAppSettings.routeRules` is also `emptyList()` with counter 10 ([settings model](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopSettingsLibrary.kt:104)). No seed-rule conversion or platform-specific starter rule was found.
- **Android splits the list and its allocator across storage.** The rule rows live in Room; `nextRouteRuleId` is read/written in preferences ([preferences load](../../app/src/main/kotlin/data/AppSettingsPreferences.kt:267), [preferences save](../../app/src/main/kotlin/data/AppSettingsPreferences.kt:512)). When Room has persisted content, load overlays the Room routing list and reconciles the counter to `max(preference counter, max rule id + 1)`; with no Room content it uses the preferences-derived `AppState` defaults ([initial load](../../app/src/main/kotlin/data/AndroidAppStateStore.kt:134), [Room restore](../../app/src/main/kotlin/data/PersistedAppState.kt:21)). This describes current storage behavior, not a new cross-platform migration policy.
- **Desktop settings collapse absent and empty route lists to the same value.** A missing file or blank file returns `DesktopAppSettings()`; a legacy JSON object with no routing keys receives model defaults during decode ([load and JSON configuration](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopSettingsLibrary.kt:114)). An explicit `"routeRules": []` also decodes to the same empty list. Save/load coverage currently verifies a nonempty rules round trip and legacy JSON with the field omitted ([settings test](../../desktopApp/src/test/kotlin/app/skipi/desktop/DesktopSettingsLibraryTest.kt:257)); there is no explicit-empty JSON case. The default kotlinx-serialization configuration does not encode default-valued fields, so a default empty route list is not a durable distinction from an omitted field on save. Do not infer an empty-vs-missing migration signal from this JSON model.
- **The global page is orphaned in the current tree and inspected history.** The shared top-level destinations contain only `Proxy`, `Configs`, and `Settings` ([destination enum](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/navigation/SkipiMainDestination.kt:13)); Android's navigation items and pager expose the same three destinations ([items](../../app/src/main/kotlin/app/AppContent.kt:125), [pager dispatch](../../app/src/main/kotlin/app/AppContent.kt:625)). Desktop dispatches the same three sections ([section switch](../../desktopApp/src/main/kotlin/app/skipi/desktop/Main.kt:1070)); its `Configs` screen edits traffic profiles. `Route` has no `Route.Routing` destination. `Route.RoutingRuleEditor` is registered ([route key](../../app/src/main/kotlin/app/navigation/Route.kt:158), [editor registration](../../app/src/main/kotlin/app/AppContent.kt:419)), but its only push call sites are inside the unmounted `RoutingPage`, so the editor is orphaned too. The read-only history check `git log --all --oneline -S 'RoutingPage(' -- app` found only `c842879 Initial commit`; `git grep -n 'RoutingPage(' <revision> -- app` at `c842879`, `cde715f`, `ad3389c`, `77e4973`, `e4c438d`, and `ff5f5d8` returned only the function declaration. Current-tree searches found no call site either. This page was not disconnected by the recent migration; exposing it now would add a new global UI flow. See the [source-audit checkpoint](../../tasks/shared-migration-20261023/r01-routing-source-audit.md).

## Android component semantics (not a reachable current flow)

The following bullets describe what the legacy Android composables do if invoked. They are a source reference for a separately authorized future feature, not evidence that users can reach these actions in the current app.

- **List and defaults commit to state immediately.** The global page has no Save action or active Back action. Domain policy, default outbound, reorder, enable/disable, and deletion call the host updater as soon as the selection/action occurs; the store publishes the new in-memory state synchronously and schedules persistence ([`RoutingPage`](../../app/src/main/kotlin/features/routing/RoutingPage.kt:175), [`AndroidAppStateStore.update`](../../app/src/main/kotlin/data/AndroidAppStateStore.kt:74)). Domain strategy options are `AsIs`, `IPIfNonMatch`, and `IPOnDemand`; the selected index is stored directly. Default outbound options are fixed `proxy`, `direct`, and `block`, plus non-custom proxy-server tags, deduplicated by tag. A blank or unavailable selected tag is displayed as `proxy` without silently writing that fallback until the user chooses an option ([dynamic options](../../app/src/main/kotlin/features/routing/RoutingPage.kt:134), [fallback](../../app/src/main/kotlin/features/routing/RoutingPage.kt:333)).
- **Rule operations use the current list.** Delete honors `enableDeletionConfirmation`: it either removes immediately or opens a confirmation dialog. Toggle and reorder apply `setRouteRuleEnabled` and `moveRouteRule` against the current `AppState` in the updater; the common list translates reorderable LazyColumn indices by subtracting its two header rows before calling `onMove` ([page callbacks](../../app/src/main/kotlin/features/routing/RoutingPage.kt:158), [shared list index mapping](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/routing/SkipiRoutingRulesList.kt:53)).
- **Editor Save commits; Cancel/Back discards.** Add opens the editor without an ID; edit opens it with a rule ID. An edit ID that no longer exists causes the editor to pop. The form is initialized from that `AppState` snapshot, while its Save callback uses the updater’s current state and upserts the submitted rule. Existing IDs replace in place; new IDs append; Cancel and toolbar Back pop without calling the updater ([editor host](../../app/src/main/kotlin/features/routing/RouteRuleComponents.kt:43), [shared form](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/routing/SkipiRouteRuleEditorForm.kt:57)). A new form starts with the localized new-rule name, `geosite:category`, default `proxy`, empty IP/process/port/protocol/network values, and enabled=true. The form trims and deduplicates newline entries; validates domain, IP/CIDR, process tokens, port list, and TCP/UDP network; protocol is trimmed but has no validity gate. Invalid values disable Save; blank domain/IP/process lists and blank port/network values are allowed by the current predicates. A new rule uses the `nextRouteRuleId` value passed when the form is composed; the state transform uses the latest counter when upserting. This is a form snapshot plus latest-list update, not a merge of concurrent edits to the same rule.
- **IDs have two boundaries.** `upsertRouteRule` preserves the counter for edits and advances it for a new ID to at least `rule.id + 1` ([shared operation](../../shared/app/src/commonMain/kotlin/app/skipi/app/routing/RouteRuleCollectionOperations.kt:14), [existing tests](../../shared/app/src/commonTest/kotlin/app/skipi/app/routing/RouteRuleCollectionOperationsTest.kt:11)). The Android shared repository also keeps a high-water counter using `maxOf(currentCounter, maxRuleId + 1)` ([Android adapter](../../app/src/main/kotlin/data/repository/AndroidAppRepositories.kt:229)); Room restore reconciles the preference counter against the maximum restored rule ID ([persisted state](../../app/src/main/kotlin/data/PersistedAppState.kt:30)). But current `RoutingPage` still uses `LocalUpdateAppState` directly ([updater wiring](../../app/src/main/kotlin/app/App.kt:140)), while `applyRouteRuleClipboardImport(Replace)` restarts imported IDs at 1 and returns a counter computed only from imported rules. The page copies that returned counter directly into `AppState` ([clipboard apply](../../app/src/main/kotlin/features/routing/RoutingPage.kt:271), [Replace/Merge behavior](../../shared/core/src/commonMain/kotlin/features/routing/usecase/RouteRuleClipboardCodec.kt:66)). Keep these source layers distinct in tests; do not assume Replace is monotonic or alter it as part of repository wiring without a source-backed decision.
- **Import/export is clipboard-driven and immediate on confirmation.** Export reports an empty-list notice or writes normalized portable JSON for the current composed `routeRules` snapshot. Import reads the clipboard, strips a BOM/whitespace, accepts the current JSON format or legacy V2Ray rules, then asks for Merge or Replace. Empty, unsupported, and no-valid-rule errors map to existing notices. On mode selection the page applies the pending decoded items to the *latest* `AppState.routeRules` and counter: Merge deduplicates by matching fields (excluding remarks and enabled), assigns IDs from the current counter, and appends; Replace starts imported IDs at 1. Existing codec tests cover normalization, legacy decode, a Merge case, and empty clipboard, but not the page-to-state/clipboard boundary or Replace mode ([page actions](../../app/src/main/kotlin/features/routing/RoutingPage.kt:202), [codec tests](../../shared/core/src/commonTest/kotlin/features/routing/usecase/RouteRuleClipboardCodecTest.kt:14)).
- **Host-owned inputs stay host-owned.** Android’s rule editor injects installed-app selection through the shared form’s optional callback. The native dialog reads `LocalAppServices.packageCatalog` on `Dispatchers.IO`, hides system apps, limits to the current user, excludes the current app package, searches label/package, and returns the selected package name to the process field ([editor callback](../../app/src/main/kotlin/features/routing/RouteRuleComponents.kt:110), [native picker](../../app/src/main/kotlin/features/routing/ui/RoutingSuggestionComponents.kt:77)). A shared/desktop form can accept a host callback; Desktop must not manufacture installed-app inventory. Geo suggestions are also host-resolved: Android uses the active traffic profile’s resource scope by default, plus global custom resource files ([suggestion provider](../../app/src/main/kotlin/features/routing/usecase/RoutingSuggestionsProvider.kt:67)). These are suggestions for global rules, not profile-owned route rules.

The `RoutingRepository` contract and `SharedApplicationStore.UpdateRouting` provide a shared state/action seam, but the orphaned Android page bypasses that action and calls `LocalUpdateAppState` directly ([repository contract](../../shared/app/src/commonMain/kotlin/app/skipi/app/repository/RepositoryContracts.kt:80), [shared action forwarding](../../shared/app/src/commonMain/kotlin/app/skipi/app/store/SharedApplicationStore.kt:253), [page updater](../../app/src/main/kotlin/features/routing/RoutingPage.kt:107)). The updater applies each transform to the store’s current state, publishes that state synchronously, and schedules persistence ([`AndroidAppStateStore.update`](../../app/src/main/kotlin/data/AndroidAppStateStore.kt:74)). Existing pure common tests cover upsert/order/ID advancement, a move, remove, setting a rule disabled, and invalid-operation no-ops; they do not cover the toggle helper or screen callbacks. The clipboard codec suite covers normalized export/import, legacy V2Ray decoding, one Merge-ID case, and empty clipboard, but not the page-to-state/clipboard boundary or Replace mode. The targeted tree search found no Android global `RoutingPage`/editor integration tests or Desktop global-routing screen tests.

## Ordered test-first slices

1. **Repository and composition wiring (complete).** The four `DesktopRoutingRepositoryTest` cases cover fresh settings reads, preservation of unrelated Desktop preferences and ID high-water, save failure without publication/state change, factory-to-store update wiring, and read-only refresh. Results and scope are recorded in the [focused verification](../../tasks/shared-migration-20261023/r01-desktop-routing-repository-verification.md). This does not establish or expose a global screen.
2. **Do not expose global list/editor/clipboard UI as a migration slice.** The history and current call graph show that `RoutingPage` and its registered `RouteRuleEditor` destination have no active Android entrypoint. Their source semantics remain documented above, but adding a global destination, connecting the orphan editor to a reachable page, or porting its clipboard flow would be new user-facing behavior, not parity work. Revisit only under an explicit product request with a new source-backed scope.
3. **Next bounded slice: saved globals in the no-active-profile Desktop generated runtime.** Add source-backed tests for the generated selected-server path with no active traffic profile, then pass the saved global rules, default outbound, and domain strategy into that path. Preserve the existing active-profile Shadowrocket routing and custom-Xray precedence. `nextRouteRuleId` remains allocation state only and must not become an Xray planner/runtime input. The concrete source gap and Android profile precedence are captured in the [runtime routing draft](r01-runtime-routing-source-contract.md); Desktop currently supplies fixed empty/Proxy routing in [`DesktopSelectedServerXrayConfigFactory`](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopSelectedServerXrayConfigFactory.kt:53).

Existing profile Rules coverage remains P04; no global-routing production or test files were changed for this audit.
