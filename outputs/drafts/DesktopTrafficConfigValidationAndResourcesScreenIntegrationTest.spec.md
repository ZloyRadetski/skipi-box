## Source-backed behavior

The shared profile DNS editor exposes a TUN DNS value, Proxy DNS and Direct DNS server lists, Direct DNS domain rules, and DNS host mappings in [SkipiTrafficConfigDnsTunnelEditors.kt](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigDnsTunnelEditors.kt:162). Android's traffic-config route also hosts this shared screen ([TrafficConfigEditorPages.kt](../../app/src/main/kotlin/features/config/TrafficConfigEditorPages.kt:288)). Domain and host entries use the shared validators in [TrafficProfileSettings.kt](../../shared/core/src/commonMain/kotlin/features/config/TrafficProfileSettings.kt:59); server entries use [XrayDnsServer.kt](../../shared/core/src/commonMain/kotlin/engine/xray/XrayDnsServer.kt:23). Malformed domain and host drafts display their localized inline errors; malformed server input displays `configs_dns_server_invalid` and is not passed to the settings callback. TUN DNS is accepted only when `isIpv4Address(value.trim())` is true. That dialog has no invalid-message resource; `settings_tun_dns_invalid` is used by the separate global settings sheet ([TunSettingsSheet.kt](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/settings/TunSettingsSheet.kt:64)), so the TUN case asserts rejection and retained value without expecting an error label. The dialog action wrapper closes after invoking Save even when a guarded callback rejects its value; the test therefore checks the retained editor value and final persisted values, rather than requiring the dialog to stay open.

`SkipiTrafficConfigDnsEditorScreen` keeps the edited settings in its screen draft and calls `saveDnsThenNavigate` on toolbar Save or Back ([SkipiTrafficConfigVisualEditorScreens.kt](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigVisualEditorScreens.kt:204)). The Desktop host routes the profile editor into DNS and saves that draft on navigation ([DesktopConfigsScreen.kt](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt:629)). The DNS test follows the shared screen's top-to-bottom layout—TUN DNS, Direct DNS server card, domain rules, then host mappings—so its harness only needs forward scrolling. It checks the temporary `configs.json` before the final editor Back, then reloads it after Back. The expected accepted values are one valid domain rule, one valid host mapping, one added supported DNS server, and one IPv4 TUN DNS value; none of the malformed drafts may appear in the final typed settings or raw `[SKIPI]` section. Raw assertions follow the codec writer in [TrafficConfigDocument.kt](../../shared/core/src/commonMain/kotlin/features/config/TrafficConfigDocument.kt:235): DNS server and domain lists are comma-joined on one line, host mappings are repeated key lines, and TUN DNS is a scalar line.

The profile-form test fixture already exercises a non-selected target profile alongside a selected sibling, checks the library envelope (`selectedConfigId`, `nextConfigId`), checks target identity metadata, and preserves `[Proxy]`, `[Rule]`, and `[Vendor]` data ([DesktopTrafficConfigProfileFormsScreenIntegrationTest.kt](../../desktopApp/src/test/kotlin/app/skipi/desktop/DesktopTrafficConfigProfileFormsScreenIntegrationTest.kt:384)). The test uses the same fixture shape and public Compose semantics, but enters through the profile row’s More menu and UI Edit action for the inactive target. It normalizes the target's hand-written SKIPI values with `toTrafficConfigState(ResourceUserAgent).withSkipiSettingsInRawConfig()` before the initial save, so screen entry does not trigger an unrelated canonicalization write.

Desktop’s Basics route opens Routing, Routing opens Resources, and Resources Back returns to Routing ([DesktopConfigsScreen.kt](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt:494), [DesktopConfigsScreen.kt](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt:556), [DesktopConfigsScreen.kt](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt:680)). The resource auto-update switch and visible interval field update `resourceSettings` through `updateSettings` as their values change ([ResourceManagementScreen.kt](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/resourcefiles/ResourceManagementScreen.kt:394)). Desktop applies each transform to the latest matching profile row and writes it back through the library callback ([DesktopConfigsScreen.kt](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt:695), [DesktopTrafficConfigEditorProfileStore.kt](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopTrafficConfigEditorProfileStore.kt:22)). There is no separate Resources Save button. The test simulates a newer same-ID profile document while Resources is open, turns auto-update on, changes its interval from 72 to 96, then reloads the temporary config JSON before Back to prove both values are already persisted. It checks that Back does not add another library transform. It then verifies the newer row marker, profile envelope, sibling row, profile metadata, resource settings, and unrelated config sections survive.

The screen harness counts successful UI library transforms separately from its external same-ID fixture update. The DNS path must have zero writes on entry and after all dialog edits, followed by exactly one write on toolbar Back. Resource settings are checked on disk before Back, then the captured transform count must remain unchanged after Back.

All profile JSON and resource files are rooted in a fresh temporary directory. The integration harness supplies inert resource services; the test does not issue network requests or access user files. The scoped baseline passed both installed cases. Physical-window/device input, clipboard, network, and external resource download behavior remain outside this test's coverage.
