# R03 — Android app-selection source audit

Read-only source audit, 24 October 2026. This records the live Android profile route, the already-shared P04 behavior, and the remaining R03 boundary. No tests, Gradle tasks, Git commands, PackageManager enumeration, clipboard access, or device I/O were run; no production or test source was changed.

## Live route and current scope

The Android route is profile-scoped. [`Route.ProxyAppList`](../../app/src/main/kotlin/app/navigation/Route.kt#L111) requires `trafficConfigId`; the only `navigator.push(Route.ProxyAppList(...))` call found is the Per-App action in the profile Basics editor, which passes `config.id` ([`TrafficConfigEditorPages.kt`](../../app/src/main/kotlin/features/config/TrafficConfigEditorPages.kt#L142)). [`AppContent`](../../app/src/main/kotlin/app/AppContent.kt#L358) dispatches that route to `ProxyAppListPage`. The page looks up the matching profile and returns when that row no longer exists ([`ProxyAppListPage.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L86)). It does not choose the active profile as its edit target. There is no global Per-App page in this route chain.

The corresponding Desktop flow is already part of P04: the profile card's More → UI Edit entry opens the profile editor; the Basics Per-App action switches to `DesktopVisualEditorSection.PerApp`, which renders the common editor with a capability notice and no fabricated installed-app rows ([`DesktopConfigsScreen.kt`](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt#L453), [`DesktopConfigsScreen.kt`](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt#L502), [`DesktopConfigsScreen.kt`](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt#L523)). The accepted P04 screen report confirms this route and explicitly leaves package enumeration and runtime enforcement in R03 ([P04 screen verification](../../tasks/shared-migration-20261023/p04-per-app-screen-verification.md#L7), [scope limits](../../tasks/shared-migration-20261023/p04-per-app-screen-verification.md#L13)).

## Behavior already moved and connected by P04

The common core owns `updateProxyAppListSelection`: checking appends supplied selection keys once, and unchecking removes only those keys ([`ProxyAppListSelection.kt`](../../shared/core/src/commonMain/kotlin/features/proxy/app/ProxyAppListSelection.kt#L6)). This preserves other configured IDs in their original order, including IDs that have no installed row. The common clipboard codec owns mode/header parsing, ID normalization, optional-mode handling, self-package filtering, and Replace/Merge data operations ([`ProxyAppListClipboardCodec.kt`](../../shared/core/src/commonMain/kotlin/features/proxy/app/usecase/ProxyAppListClipboardCodec.kt#L24)). The P04 Android baseline and common tests already characterize these functions; see [foundation verification](../../tasks/shared-migration-20261023/p04-per-app-foundation-verification.md#L7) and [`ProxyAppListSelectionOperationsTest`](../../shared/core/src/commonTest/kotlin/features/proxy/app/ProxyAppListSelectionOperationsTest.kt#L9).

The common `TrafficConfigEditorController` now sets mode, changes selections, and applies imports against the profile ID supplied by the screen ([`TrafficConfigEditorController.kt`](../../shared/app/src/commonMain/kotlin/app/skipi/app/config/TrafficConfigEditorController.kt#L115)). Android creates the controller with an updater that transforms only the row with that ID ([`TrafficConfigEditorPages.kt`](../../app/src/main/kotlin/features/config/TrafficConfigEditorPages.kt#L159)); Desktop's profile store transforms the latest persisted row by ID ([`DesktopTrafficConfigEditorProfileStore.kt`](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopTrafficConfigEditorProfileStore.kt#L22)). The editor operations are immediate: changing mode copies only `proxyAppListMode`, leaving selected IDs intact; selection uses the common helper; import uses the existing Replace/Merge operation and Android count formula.

[`SkipiTrafficConfigProxyAppListEditorScreen`](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigProxyAppListEditorScreen.kt#L64) owns the mode menu, More menu, clipboard callbacks, pending import, Replace/Merge dialog, localized decode errors, and notices. On a valid import it opens the dialog; dismiss clears pending import, and a handled save failure keeps confirmation available rather than showing success ([screen callbacks](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigProxyAppListEditorScreen.kt#L119)). Android supplies the real application package name, clipboard callbacks, current user ID, search field, user tabs, and app-list slot ([`ProxyAppListPage.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L133)). The common codec receives `currentUserId ?: 0`; this is the existing fallback for bare clipboard package names, not evidence of a Desktop or Android-user enumeration result ([screen](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigProxyAppListEditorScreen.kt#L134)).

The shared full-screen scaffold only renders a Save icon when `onSave` is non-null ([`SkipiTrafficConfigScaffold.kt`](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigScaffold.kt#L47)). The Per-App screen does not provide `onSave`; there is no draft or Save transaction. Desktop passes `onBack` to return to Basics ([`DesktopConfigsScreen.kt`](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt#L523)). Android's call omits `onBack`, so the common scaffold gets its default null; Android route/system navigation handles leaving the page. In both hosts, leaving does not undo already-committed Per-App edits.

The Desktop editor passes `currentUserId = null`, `selfPackageName = ""`, and a notice stating that it has neither Android app inventory nor per-app enforcement; it still persists profile mode and clipboard ID edits. This preserves existing data without claiming Desktop PackageManager or VPN behavior ([`DesktopConfigsScreen.kt`](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt#L523), [`strings.xml`](../../shared/ui/src/commonMain/composeResources/values/strings.xml#L880)).

## Stored profile data and runtime policy

`TrafficConfigState` already carries `proxyAppListMode` and `proxyAppListSelectedApps` as portable profile fields ([`TrafficConfigDocument.kt`](../../shared/core/src/commonMain/kotlin/features/config/TrafficConfigDocument.kt#L39)). The persisted mode numbers remain 0 blacklist, 1 whitelist, 2 global ([`SkipiConfigDocument.kt`](../../shared/core/src/commonMain/kotlin/features/config/SkipiConfigDocument.kt#L54)). The profile codec reads `per-app-mode` and repeated `per-app-package` values, trims package values, drops blanks, and deduplicates in order; it writes the same named mode and repeated package keys after trimming/deduplication ([reader](../../shared/core/src/commonMain/kotlin/features/config/TrafficConfigDocument.kt#L91), [writer](../../shared/core/src/commonMain/kotlin/features/config/TrafficConfigDocument.kt#L202)). This is normalized field round-trip behavior, not a promise to retain malformed whitespace or duplicate raw entries byte-for-byte.

Android preferences serialize the list of `TrafficConfigState` rows and include both Per-App fields in `PersistedTrafficConfig` ([`AppSettingsPreferences.kt`](../../app/src/main/kotlin/data/AppSettingsPreferences.kt#L75), [`AppSettingsPreferences.kt`](../../app/src/main/kotlin/data/AppSettingsPreferences.kt#L509), [`AppStateJson.kt`](../../app/src/main/kotlin/data/AppStateJson.kt#L118)). Backup has matching `AppBackupTrafficConfig` fields and copies them both directions ([`AppBackupModels.kt`](../../shared/core/src/commonMain/kotlin/features/backup/AppBackupModels.kt#L361), [`AppBackupMappers.kt`](../../shared/core/src/commonMain/kotlin/features/backup/AppBackupMappers.kt#L81)). Thus existing profile storage and backup have the fields needed for a host without policy enforcement.

`AppState` also has effective runtime Per-App fields and Android has a root preference key for the mode. Those are not a separate Per-App editor route: when VPN start state is built, `withActiveTrafficConfigApplied()` copies the active profile's mode and IDs onto the effective `AppState` ([`TrafficConfigRuntime.kt`](../../app/src/main/kotlin/app/TrafficConfigRuntime.kt#L13)); `VpnXrayConfig` then creates `VpnApplicationPolicy` with Android's current user ID ([`VpnXrayConfig.kt`](../../app/src/main/kotlin/engine/vpn/VpnXrayConfig.kt#L155)). The host-specific service maps whitelist to allowed apps, blacklist to disallowed apps, and global to self-exclusion; an empty installable whitelist falls back to denying installed packages because Android treats an empty allowlist as all apps ([`SkipiVpnService.kt`](../../app/src/main/kotlin/engine/vpn/SkipiVpnService.kt#L419)). Package installation checks and `VpnService.Builder` calls remain OS work. The strict-full-tunnel override also remains part of the existing Android runtime path.

## Android list source: portable projection mixed with host I/O

[`ProxyAppListData.kt`](../../app/src/main/kotlin/features/proxy/app/model/ProxyAppListData.kt#L19) contains plain package facts (`packageName`, label, user ID, UID, system flag), user-tab and row projection records, and the icon request model. The same file also contains both host-bound loading and portable transformations. `loadProxyAppListPackages` selects the Android package scope, requests package info, excludes the app's own package, deduplicates and sorts ([same file](../../app/src/main/kotlin/features/proxy/app/model/ProxyAppListData.kt#L60)). `prepareProxyAppListData` groups by user, builds app rows, derives shared-UID selection keys, and searches a trimmed query against label or package name case-insensitively ([same file](../../app/src/main/kotlin/features/proxy/app/model/ProxyAppListData.kt#L101), [row matching](../../app/src/main/kotlin/features/proxy/app/model/ProxyAppListData.kt#L189)). `sortedForProxyAppListRefresh` puts selected app/UID groups first and then applies stable name/package tie-breaks ([same file](../../app/src/main/kotlin/features/proxy/app/model/ProxyAppListData.kt#L213)). Tab counts only count rows the current inventory represents; unknown configured IDs are not removed by this projection.

There are two live consumers of this mixed file. The Per-App page uses the loader, projection, and refresh sort. `ProcessAppPickerDialog` in routing suggestions also uses the Android package loader and `AppPackageEntry` ([`RoutingSuggestionComponents.kt`](../../app/src/main/kotlin/features/routing/ui/RoutingSuggestionComponents.kt#L77)). Therefore a common projection extraction must retarget that consumer or keep a narrow Android-facing record/adapter for it; moving the entire `ProxyAppListData.kt` file would incorrectly move provider and icon responsibilities.

The page's Compose state and effects are currently located in Android-host files: query debounce (150 ms), system-app toggle, refresh seed, loading and refreshing flags, prepared data, user tab selection, pager synchronization, and provider loads live in [`ProxyAppListPageState.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L39). `LaunchedEffect` cancellation is rethrown; other load failures clear the list and show the Android notice; `finally` clears loading/refresh flags ([same file](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L224)). The page gives automatic loading a 500 ms minimum visible time ([`ProxyAppListPage.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L67)). As classified below, query/tab/pager presentation state is portable; provider lifecycle, loading/error notices, and Android elapsed-time coordination stay with the host.

### Portable presentation still in the Android host

P04 intentionally leaves `headerContent` and `appContent` as host slots on the shared editor screen ([slot contract](../../shared/ui/src/commonMain/kotlin/app/skipi/ui/config/SkipiTrafficConfigProxyAppListEditorScreen.kt#L80)). Android currently fills them with a search field, optional user tabs, and the list/pager ([Android slot call](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L146), [list content](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L296)). Those slots are an integration seam, not proof that their entire content is Android-specific.

The search control, empty state, tab labels/counts, and app-row body are portable Compose presentation in [`ProxyAppListComponents.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListComponents.kt#L58). The app row displays the package label/name, package ID, UID/shared-UID marker, checked state, and disabled state for global mode ([row](../../app/src/main/kotlin/features/proxy/app/ProxyAppListComponents.kt#L89)). The 150 ms query debounce, selected user ID, derived tabs, and pager/tab synchronization are also host-independent UI state and interaction ([state/effects](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L45), [debounce](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L124), [pager](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L161)). For R03's “portable presentation” criterion, these controls and the row/list presentation should move into `shared/ui` and remain used through Android's existing slots; that does not require a Desktop catalog or fake rows.

The row is structurally portable except for its icon child and Android-only resource references. `AppIcon` creates a Coil model from `ProxyAppIconRequest` ([icon child](../../app/src/main/kotlin/features/proxy/app/ProxyAppListComponents.kt#L262)); `AsyncImage`, the request model, and its eventual PackageManager-backed fetcher must remain supplied by Android. A common row can accept an icon composable slot plus package facts and selection callbacks, preserving its current label/package/UID/SUID/checkbox behavior. The component currently references `app.R` and the Android compatibility alias `ui.AppTheme`; `shared/ui` should use its own generated `Res` strings and shared theme API (`ui.AppTheme` is a compatibility wrapper over shared theme colors, [`Theme.kt`](../../app/src/main/kotlin/ui/Theme.kt#L50)). The common search/empty components can likewise use shared strings. If tab confirmation haptics are retained, expose feedback as an optional callback; it is not part of the tab-count or selection logic.

Keep `ProxyAppListPage` as the Android host that supplies real inventory and user-space values and chooses `currentUserOnly` based on Android VPN-service mode. Keep PackageManager scope selection, own-package exclusion, provider/user conversion, system-app toggle state, refresh/loading/error/cancellation handling and toast notices in the Android adapter. The current 500 ms minimum automatic-loading overlay measures with Android `SystemClock.elapsedRealtime()` ([overlay timing](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L195)); leave this timing/lifecycle coordination host-side. The loading indicator itself may be shared presentation later, but it is not a reason to move provider lifecycle into common UI. The P04 `appContent` slot may continue to delimit the native inventory/loading shell while that shell composes the shared list presentation for actual rows.

The actual provider is narrower than the projection's shape suggests. `AndroidPackageRepository.listPackages` and `getPackagesInfo` obtain current-user package records; system-app filtering uses Android application flags ([`AndroidPackageRepository.kt`](../../app/src/main/kotlin/system/AndroidPackageRepository.kt#L18), [`AndroidPackageRepository.kt`](../../app/src/main/kotlin/system/AndroidPackageRepository.kt#L53)). The Per-App loader uses `all` versus `user` package scope for the system-app toggle. In normal run mode the model can group records by user ID, but the current provider returns the current user's packages. In VPN-service mode the page fixes the displayed list to the current user. Its current-user fallback uses ID 0 only when the provider call fails ([`ProxyAppListPageState.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L197)). In the non-VPN path, `loadProxyAppListUserSpaces` tries `listAndroidUsers()` first; the current `AndroidUserSpaceProvider.listAndroidUsers()` returns just the current Android user ([`AndroidUserSpaceProvider.kt`](../../app/src/main/kotlin/system/AndroidUserSpaceProvider.kt#L18)). Consequently the later `listAndroidUserSpaces()` call is a fallback on error/empty result, not the normal profile enumeration path. Do not claim that the live list currently enumerates every Android profile.

Icons are Android-only: the card sends `ProxyAppIconRequest` to Coil ([`ProxyAppListComponents.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListComponents.kt#L262)); `AndroidAppIconFetcher` uses `PackageManager.getApplicationInfo` and `loadIcon` ([`AndroidAppIconFetcher.kt`](../../app/src/main/kotlin/system/AndroidAppIconFetcher.kt#L25)). Keep icon requests and retrieval in the Android adapter. Similarly, keep user-space and PackageManager data acquisition, system-scope selection, self-package identity, loading/cancellation/toast handling, and actual VPN application policy in Android.

## Remaining R03 gap

The P04 shared editor, immediate profile-ID controller operations, Desktop route, storage fields, and clipboard path are already present. Do not duplicate them in R03. The remaining portable work has two connected parts: move the supplied-record projection out of `ProxyAppListData.kt` and `ProxyAppListPageState.kt` into common core, then move the search/tab/empty/list-row presentation and its pure UI state out of `ProxyAppListComponents.kt` and the Android slot body into `shared/ui`. The current Android page can continue to connect those shared pieces through P04's `headerContent` and `appContent` slots. Real Android inventory/user-space/icon integration and VPN-policy smoke remain platform work; Desktop must keep editing and preserving profile data without fabricated inventory or enforcement. This matches [R03's planned boundary](../../tasks/plan.md#L630), while the accepted P04 report documents its already-completed editor slots and R03 remainder ([P04 report](../../tasks/shared-migration-20261023/p04-per-app-screen-verification.md#L72)).

## Smallest tests-first slice to start R03

Start with one pure projection extraction; do not include PackageManager loading, Compose navigation, or service enforcement in this first slice. Before production changes, add Android source-oracle tests against today's `prepareProxyAppListData` and `sortedForProxyAppListRefresh`, using only supplied record fixtures. Then add common projection tests against the intended common API and capture its expected compile/API RED. Existing P04 helper, controller, clipboard, profile-store, and Desktop screen tests already cover unknown-ID retention and immediate editing; keep those expectations and avoid duplicating them. Treat the portable Compose extraction as the next R03 slice after the projection contract is pinned: common UI tests should cover query input/debounce, tabs/counts and selection state, empty/result rendering, and global-mode row disablement, while the Android-facing icon slot remains a host seam. Do not broaden that UI slice into package loading or Desktop inventory.

A narrow common contract can live in `shared/core/src/commonMain/kotlin/features/proxy/app/ProxyAppListProjection.kt` with plain package facts (`packageName`, `appLabel`, `userId`, `uid`, `system`), plain user-space values (`id`, `name`), projected rows (`key`, package, `sharedUid`, `selectionKeys`), prepared `allItemsByUser`/`visibleItemsByUser` plus displayed users, and pure functions for preparation, refresh sorting, and tab counts. The Android wrapper keeps `ProxyAppIconRequest`, provider calls, `InstalledPackageInfo` and `AndroidUser` conversion, system scopes, and Compose state. Preserve current fixed-user behavior, including normalizing Android UID to app ID when it remaps a package to a fixed user. Use the distinct filename `ProxyAppListProjection.kt`, not another `*ProxyAppListData.kt` JVM facade name.

Use the same fixture cases on Android baseline and common tests:

- A trimmed mixed-case query matches by app label or package name and does not change the full user-grouped rows.
- Provided user spaces remain sorted and package records with an otherwise unlisted user produce the source fallback label `User <id>`.
- Two packages with a shared UID in one user produce one row per app with the complete ordered `userId:packageName` key set; equal app IDs in different users stay separate in normal mode.
- Fixed-user projection preserves the source UID-to-app-ID grouping/remap and deduplicates same-package rows as the current implementation does.
- Refresh sorting puts selected groups first and retains the existing group/name/package tie-break order.

These tests exercise supplied records only. System-versus-user package scope, current-user provider behavior, error/cancellation and native icon loading belong to later Android-adapter verification. Runtime policy still needs the R03 Android smoke specified by the plan. The existing Android selection test presently pins unknown/legacy ID retention and shared-UID toggles; no projection/search test was found in the Android/shared test roots searched for this audit ([Android selection test](../../app/src/test/kotlin/features/proxy/app/ProxyAppListSelectionTest.kt#L11), [common selection test](../../shared/core/src/commonTest/kotlin/features/proxy/app/ProxyAppListSelectionOperationsTest.kt#L9)).
