| Schedule and worker rules | The common spec keeps connected-network eligibility, unique `UPDATE` work, and a 15-minute exponential-backoff base. Android maps this to WorkManager and tracks/cancels scheduled IDs. The shared periodic state records interval completion, classified retries, and retry deadlines. Desktop’s subscription updater is owned at `Main` app-composition lifetime rather than by Proxy Home; it uses the shared spec/state and common worker outcome policy. See `shared/core/.../SubscriptionRefreshScheduling.kt`, `SubscriptionPeriodicWorkState.kt`, `shared/app/.../SubscriptionWorkerPolicy.kt`, and `app/src/main/.../AndroidSubscriptionScheduleGateway.kt`. |
| Connected admission, cancellation, and no false success | Desktop passes `isDesktopNetworkConnected` into both the coordinator and updater. The predicate reads operating-system interface state (an up non-loopback interface), without an external reachability probe. The coordinator checks again after acquiring admission; offline work returns `null` and stays due. The updater cancels a running child on an offline due pass, preserves its schedule, and records a result only while both its coroutine and the current target entry remain active. Missing/disabled/blank scheduled rows are an Android-compatible no-op success; commit failures map to permanent failure, classified load failures map to retry or failure, and cancellation propagates. See `DesktopSubscriptionRefreshCoordinator.kt`, `DesktopSubscriptionAutoUpdater.kt`, `DesktopResourceAutoUpdater.kt` (`isDesktopNetworkConnected`), and `Main.kt`. |
| Request settings | Android derives proxy and Age settings from the saved group and device-header/timeout from current Android settings. Desktop derives the same fields from the latest saved row, current Desktop settings, and the live Core listener snapshot; it does not use caller-captured options from before coordinator admission. The field behavior is wired. Existing defaults remain host-specific: Android’s fetch timeout defaults to 10 seconds and Desktop’s to 30 seconds. I found no S03 instruction to replace the existing Desktop default, so this audit records the difference without treating it as a new feature or claiming default parity. See `SubscriptionUpdateUseCase.kt`, `DesktopLocalProxyRuntime.kt`, `DesktopSettingsLibrary.kt`, and `Main.kt`. |
