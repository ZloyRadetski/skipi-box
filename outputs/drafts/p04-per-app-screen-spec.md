# P04 Desktop Per-App screen test specification

23 October 2026. This is a source-backed acceptance spec for the next P04 Desktop UI slice. It guides eight cases in a new `DesktopTrafficConfigPerAppScreenIntegrationTest`; it does not describe a completed UI implementation.

## Source contract

- Profile-card More → UI Edit opens Basics for the clicked profile ID and does not select it. Per-App must continue editing that inactive target by ID while another profile remains selected. The route is implemented by `DesktopConfigsScreen`'s profile context menu and the current integration baseline is in `DesktopTrafficConfigCollectionScreenIntegrationTest`.
- Android Per-App mode, selection, clipboard import, and export callbacks commit immediately against `trafficConfigId`; there is no Save or discard draft. The source behavior is in [`ProxyAppListPage.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt) and [`ProxyAppListPageState.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt).
- Clipboard text uses the shared codec in [`ProxyAppListClipboardCodec.kt`](../../shared/core/src/commonMain/kotlin/features/proxy/app/usecase/ProxyAppListClipboardCodec.kt). A missing mode keeps the current mode; Replace and Merge follow `ClipboardImportMode`, and import errors map to the existing localized resource keys. Bare names must use the Android source fallback `currentUserId = 0` when no selected user is available; this is only a serialization fallback, not Desktop user discovery. The Android app-package identity remains a host input and Desktop must not invent one.
- The shared editor controller and Desktop latest-row store already exist in [`TrafficConfigEditorController.kt`](../../shared/app/src/commonMain/kotlin/app/skipi/app/config/TrafficConfigEditorController.kt) and [`DesktopTrafficConfigEditorProfileStore.kt`](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopTrafficConfigEditorProfileStore.kt). UI work should use those APIs and preserve the latest profile/library envelope.
- On Android, confirming a valid import after the target profile has disappeared closes the dialog and reports Imported 0; the page does not recreate the missing row. The behavior comes from `ProxyAppListPage`'s missing-active-config early return followed by clearing `pendingAppListImport` and notifying the app-level tip.
- On Android, a thrown profile update prevents the import confirmation handler from reaching its pending-dialog clear and success notification. The shared Desktop editor controller catches a save exception through its existing `onSaveFailure` callback and returns `TrafficConfigEditorResult.Failed`; the pending import should therefore stay available for retry and must not produce an Imported success notice.
- Desktop has no Android package inventory, icons, user spaces, or per-app VPN enforcement. The page must present a localized `configs_per_app_desktop_notice`, expose mode and clipboard editing, and omit fake app rows, system-app controls, search, and a package-name text field. Tests resolve the resource with `getString(Res.string.configs_per_app_desktop_notice)` and assert it is visibly laid out; they do not hard-code its prose.

## Required cases

1. From profile-card More → UI Edit, open Per-App for inactive profile 7 while profile 3 remains selected. Change mode to whitelist through the mode menu. Verify the temporary `configs.json` is updated immediately, selected IDs and unrelated sections/metadata/order/next ID remain intact, and no Save action is present. Back returns to Basics without another library transform or rollback.
2. Inject clipboard text containing `mode=whitelist`, one bare package name, and one explicit `10:package` ID. Import reports two detected entries; confirm Replace. Verify the saved IDs are `0:bare-package` and `10:explicit-package`, the mode is whitelist, the localized Imported count is two, and the remaining library/document data is unchanged.
3. Open the import confirmation for clipboard data with `mode=global` and an existing plus new ID. Before choosing Merge, persist a late same-ID edit with mode whitelist whose latest selected IDs already include the imported new ID plus another late ID; also append sibling 15 and advance `nextConfigId` to 40. Merge must use the latest repository row, preserve its name/source/lock/timestamp/document and late selected ID, retain sibling/order/selected profile/counter, apply the included global mode, and report Imported 0 (the latest row already contains all imported IDs).
4. With a valid import dialog open for profile 7, remove only that row from the temporary `configs.json` while the current Compose screen still holds its stale snapshot. Confirm Merge. The controller must observe the missing latest row, close the dialog, report Imported 0 in the catalog status, and leave only selected sibling 3 in storage without changing the selected ID or next-ID counter. The test simulates an external file update without publishing it to the screen before confirmation; it does not test a UI-driven delete.
5. Inject a clipboard entry with a nonnumeric user prefix. Show the localized `proxy_app_list_import_invalid_user` notice, show no Replace/Merge dialog, and leave the entire persisted library and transform count unchanged.
6. Export writes the current mode and ordered selected IDs to the injected in-memory clipboard and does not transform the profile library. In the More menu, assert there is no localized Show system apps action. On the page, assert there are no app rows, search field, or editable package-name field.
7. Render the actual body, open mode menu, and import confirmation at both 390×844 and 1100×800. Save six stable PNGs. Assert the localized capability notice, mode/more controls, menu option, dialog title/count/actions, and visible Back/action controls fit the viewport. Dismiss the menu/dialog through actual option and Merge actions before ending each scene. Assert only the resulting mode/ID storage semantics; do not require a long raw document field to fit in the viewport.
8. For both Merge and Replace, inject a one-shot repository save failure after the profile transform is computed but before `configs.json` is written or the library is published. Assert the on-disk and displayed libraries remain unchanged, the import dialog and detected-count message remain open, no Imported success message appears, the clipboard is read only once and never written, and the failed-save candidate contains the expected mode and selected IDs. This failure injection is test-harness-only and exercises the existing `onSaveFailure` path.

## Test boundary

Use a real temporary `configs.json`, `DesktopTrafficConfigRepository`, and public Compose semantics actions for More → UI Edit, Basics → Per-App, mode selection, import/export, confirmation, and Back. Inject `readPerAppClipboardText: suspend () -> String?` and the existing `copyTextToClipboard` callback so tests do not access the operating-system clipboard. Use fresh `ImageComposeScene` instances for each viewport. All eight cases are test-only characterization; the shared UI and Desktop callback wiring remain unimplemented until after API/behavior RED.
