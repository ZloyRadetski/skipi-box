## Android source correction before transfer

The existing global-row predicate also displays non-StrategyGroup servers stored under group -2, as pinned by the [group-list baseline](p04-config-group-list-verification.md). A normal row click and Duplicate safely ignore such a record, while the context menu's Edit previously used `server as StrategyGroup` and threw. The list predicate remains unchanged; fixing that unsafe menu cast is an explicit behavior correction, not a claim of unchanged Android parity.

Three Android tests were written before production changes. They require Edit to preserve the original StrategyGroup instance, its explicit or null server ID, group/return group -2 and `deleted=false`, and to return no editor result for another server type. The missing-helper API RED took 23 seconds (`outputs/p04-global-group-edit-android-helper-api-red-20261022.log`). After extracting the actual unsafe source path into the helper and wiring the menu through it, the unchanged tests reproduced the defect: **2 passed, 1 ClassCastException in 11 seconds**, XML timestamp `2026-10-22T04:55:05.853Z`. Log: `outputs/p04-global-group-edit-android-behavior-red-20261022.log`; preserved XML: `outputs/p04-global-group-edit-android-behavior-red-reports-20261022/`.

Only then was the cast changed to `as? StrategyGroup ?: return null`. The original instance and result fields are retained for valid groups. Root reviewed the diff and ran the same three tests alongside the four unchanged group-list oracle tests: **7/7 GREEN in 9 seconds**, zero failures/errors/skips. Log: `outputs/p04-global-group-edit-android-safe-green-20261022.log`; XML/counts: `outputs/p04-global-group-edit-android-safe-reports-20261022/`, timestamp `2026-10-22T04:57:39.926Z`.
