# P03 profile auto-refresh research

Status: source review only. This note identifies the current Android contract and the Desktop boundary for a possible next P03 slice after the P04 collection checkpoint. No tests or production code were changed here. P02, P03, and P04 remain open.

## Current shared operations and host boundaries

`TrafficConfigProfileRefreshOperations` is the shared policy for the manual unlock decision and refresh commit. `requestManualRefresh` asks the host to confirm when the captured profile is locked; `confirmUnlockAndRefresh` produces a manual request with `unlock=true`; `apply` parses the fetched document and applies the existing Android rules. In automatic mode it imports response settings while retaining the latest row's `updateLocked`, `autoUpdate`, profile interval, and resource auto-update settings. It writes the captured source URL and timestamp. See [TrafficConfigProfileRefreshOperations.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/shared/app/src/commonMain/kotlin/app/skipi/app/config/TrafficConfigProfileRefreshOperations.kt:32).

The shared schedule model is `TrafficConfigRefreshTarget`, with distinct profile and geo-resource eligibility in [TrafficConfigRefreshScheduling.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/shared/core/src/commonMain/kotlin/features/config/runtime/TrafficConfigRefreshScheduling.kt:13). `TrafficConfigScheduler.reconcile` derives profile and geo work independently, cancels previously tracked IDs no longer eligible, enqueues desired specs, and stores the resulting IDs. The profile rule is `autoUpdate && !updateLocked && sourceUrl.isNotBlank() && parseSubscriptionSchedule(updateInterval) is Enabled`; geo eligibility is only `resourceAutoUpdate` plus an enabled resource interval. The shared parser treats blank and non-positive values as disabled, and positive intervals below fifteen minutes, malformed values, or millisecond overflow as invalid: [SubscriptionSchedule.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/shared/core/src/commonMain/kotlin/features/subscription/SubscriptionSchedule.kt:18).

The Android adapters are currently connected:

- [TrafficConfigScheduler.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/features/config/runtime/TrafficConfigScheduler.kt:9) maps each `TrafficConfigState` into the shared target.
- [SkipiApplication.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/app/SkipiApplication.kt:102) observes a distinct key containing profile ID, source URL, lock, auto-update, profile interval, and resource auto-update/interval, then reconciles against the latest profiles. The key does not depend on selection, so periodic profile refresh is per eligible profile.
- [TrafficConfigPage.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/features/config/TrafficConfigPage.kt:248) owns manual fetch and unlock UI. [TrafficConfigAutoUpdateWorker.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/features/config/runtime/TrafficConfigAutoUpdateWorker.kt:19) owns automatic fetch and commit.
- [AndroidTrafficConfigScheduleGateway.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/features/config/runtime/AndroidTrafficConfigScheduleGateway.kt:39) maps profile specs to unique periodic WorkManager requests with the profile ID input, connected-network constraint, exponential backoff from the shared 15-minute base, and `ExistingPeriodicWorkPolicy.UPDATE`. It cancels by the same unique name and persists its tracked ID set in preferences. Geo work uses a separate worker, tag, unique name, and tracked ID set.

P02 collection operations are not an outstanding P03 algorithm: profile list edits already use shared create/duplicate/delete/update operations, and Android profile edits go through the state-store update wrapper. The shared group reconciler is invoked after Android config edits, selection changes, and automatic refresh; Desktop config-library changes trigger its Desktop adapter. The common commit/reconciliation boundary is described in [ConfigProxyGroupReconciler.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/shared/app/src/commonMain/kotlin/app/skipi/app/proxy/ConfigProxyGroupReconciler.kt:29), with host wiring in [App.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/app/App.kt:142) and [DesktopTrafficConfigProxyGroupReconciler.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/desktopApp/src/main/kotlin/app/skipi/desktop/DesktopTrafficConfigProxyGroupReconciler.kt:19).

## Exact Android profile worker contract

`TrafficConfigAutoUpdateWorker.doWork` has these observable results and steps:

1. A missing/invalid input ID (`-1`) returns `Result.success()`. A context that is not a `SkipiApplication` returns `Result.failure()`. A deleted/missing profile returns success. A currently disabled, locked, or URL-empty profile also returns success without fetching.
2. The worker captures the profile row before fetching, trims its URL, normalizes that row's resource UA with `normalizeSkipiUserAgent`, and creates fetch options from a later current `AppState` snapshot with `useRunningProxy = state.proxyRunning`. The comment explicitly requires background fetches to use the running tunnel when it is active.
3. It normalizes fetched content to one trailing newline and analyzes the Shadowrocket document. Any error diagnostic returns `Result.retry()`.
4. It calls `stateStore.update` with `withCommittedTrafficConfigRefresh(configId, ..., mode = Automatic)`, then reconciles config-derived proxy groups, then returns success. The update transforms the latest same-ID row; it does not compare a revision, reject a late response, or re-check eligibility after fetch. If the profile was deleted while fetching, the update is a no-op and the worker still reconciles and reports success.
5. The whole fetch/parse/commit block is inside `runCatching { ... }.getOrElse { Result.retry() }`. Thus the current implementation maps caught exceptions to retry; it has no explicit `CancellationException` rethrow. Preserve and test this observed source behavior during an exact transfer rather than borrowing cancellation semantics from a different host loop.

The worker's automatic commit intentionally writes the response to the latest same-ID row without revision/CAS protection. It updates the fetched raw document, parsed portable fields, captured URL, and timestamp, but retains the latest scheduling fields via `TrafficConfigProfileRefreshOperations.apply(Automatic)`. This matches the manual/automatic commit tests and the P03 plan's explicit no-CAS constraint.

Android also schedules one-time **geo-resource** work when the active profile's custom GeoIP/GeoSite URL projection changes. `SkipiApplication` drops the initial observation, then enqueues one-time work for a positive active ID using `ExistingWorkPolicy.REPLACE`; that worker only updates resource files and checks `resourceSettings.autoUpdate`. It is separate from profile-document refresh: [SkipiApplication.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/app/SkipiApplication.kt:122), [AndroidTrafficConfigScheduleGateway.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/features/config/runtime/AndroidTrafficConfigScheduleGateway.kt:93), [ResourceAutoUpdateWorker.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/features/config/runtime/ResourceAutoUpdateWorker.kt:19).

## Confirmed Desktop gap and separate resource path

Desktop manual profile refresh is already connected to the shared request and commit operations: [DesktopConfigProfileRefresh.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigProfileRefresh.kt:12) adapts a stored profile for the shared lock decision, and [DesktopConfigsScreen.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/desktopApp/src/main/kotlin/app/skipi/desktop/DesktopConfigsScreen.kt:355) fetches the captured URL, re-reads the latest same-ID library row, calls shared `apply`, then persists with `DesktopConfigLibraries.update`.

Desktop currently wires no profile periodic scheduler or automatic profile-document worker. Its [Main.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/desktopApp/src/main/kotlin/app/skipi/desktop/Main.kt:526) observes targets through `DesktopResourceAutoUpdater`; that updater's periodic scheduler calls `target.geoRefreshWorkSpecOrNull()` and the due callback is `DesktopResourceFileServices.updateAutomatically`, so it handles geo/resource files only. Although `TrafficConfigRefreshTarget` carries `autoUpdate`, `updateLocked`, `sourceUrl`, and `updateInterval`, that Desktop resource schedule does not consult those fields. The current loop has explicit cancellation handling and resource-specific retries; it must not be reused as evidence for profile refresh cancellation or commit behavior.

Android defaults relevant to eligibility: a default `TrafficConfigState` has profile `autoUpdate=false` and empty profile interval, while `TrafficConfigResourceSettings` defaults to resource `autoUpdate=true` and interval `24`. Android's application default and new-profile adapter fill the resource UA with `DefaultSubscriptionUserAgent`. The shared defaults are in [TrafficConfigDocument.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/shared/core/src/commonMain/kotlin/features/config/TrafficConfigDocument.kt:25) and Android's UA adapter is in [AndroidTrafficConfigDefaults.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/app/src/main/kotlin/features/config/AndroidTrafficConfigDefaults.kt:8). The Desktop profile library materializes its absent-UA fallback as `Skipi/<version>/Desktop`; it currently has no periodic profile worker to consume the shared profile eligibility rule.

## Smallest shared execution boundary

The portable part missing from Desktop is the worker's **fetch → normalize and validate → commit latest row → reconcile generated groups** orchestration. Keep that in `shared/app` as one automatic profile-refresh executor, and make the host responsibilities callbacks/ports rather than copy this sequence into both worker and Desktop updater. Its minimum inputs are the profile snapshot captured when the job starts, a fetch callback receiving the captured trimmed URL and host-prepared user agent, an atomic host callback that applies a supplied transform to the latest same-ID `TrafficConfigState`, a timestamp provider, and a host reconciliation callback. The common executor should retain Android's existing `TrafficConfigProfileRefreshOperations.apply(..., Automatic)` commit transform, `trimEnd() + "\n"` normalization, `analyzeShadowrocketConfig()` error gate, and the order of commit then group reconciliation. It should report only the existing worker outcomes needed by the host (skip/success/retry); it must not invent stale-response checks, a new conflict policy, or a new retry policy.

The callback boundary preserves existing snapshots and side effects:

- Android still validates WorkManager input and `SkipiApplication` context, reads the initial profile, and builds fetch options immediately before the fetch from the latest app state, including `useRunningProxy = state.proxyRunning`. Its fetch callback calls `subscriptionFetcher`; its commit callback performs `stateStore.update` against the latest state; its reconcile callback dispatches the existing config-proxy-group reconciliation. WorkManager `Result.success()` / `failure()` / `retry()`, unique work, connected-network constraints, tags, preference-backed scheduled IDs, and backoff remain Android-owned.
- Desktop's real profile timer and network-connected check remain Desktop-owned. It uses the same common profile eligibility/work-spec rules and calls the executor with its subscription-fetch adapter. Its commit callback transforms the latest library row through the existing shared automatic apply operation and persists with `DesktopConfigLibraries.update`; its reconcile callback uses the existing Desktop group reconciler. The existing `DesktopResourceAutoUpdater` remains geo-only and must not host profile refresh, because its schedule, retry, supersession, and cancellation rules differ.
- Common code controls the portable response steps and the callback order. It does not own WorkManager, an in-process timer, network-interface probing, Android app-context validation, HTTP headers/proxy setup, host persistence, or the shared-store/library implementation details.

The Android worker currently wraps fetch, validation, update, and reconciliation in `runCatching { ... }.getOrElse { Result.retry() }`. As a result, any thrown error, including a `CancellationException` thrown inside that block, maps to the worker's retry result; there is no explicit cancellation rethrow. Preserve and test this observed profile-worker behavior when extracting the executor and map the shared outcome in each host. Do not import the Desktop geo loop's explicit `CancellationException` rethrow or its retry scheduling into profile refresh. The common scheduling eligibility/spec logic in [TrafficConfigRefreshScheduling.kt](/home/vqsego/TorvaldsVPN/Skipi/skipi-box/shared/core/src/commonMain/kotlin/features/config/runtime/TrafficConfigRefreshScheduling.kt:56) remains independent of this execution coordinator.

## Selected first execution slice after collection verification

Root selected an internal Android execution seam before moving it to shared. It receives a nullable captured `TrafficConfigState`, a fetch callback taking that same profile and its trimmed URL, a Unit-returning commit callback taking ID/normalized document/captured URL, and a reconcile callback. Its two results are Success and Retry: source eligibility skips already return WorkManager Success, so a third public skipped outcome is unnecessary. Eligibility remains before `runCatching`; fetch, document normalization/analysis, commit and reconciliation remain inside it, including the source's caught-cancellation-to-retry behavior.

Android's input `-1`, application-context guard and snapshot lookup remain in `doWork` in their original order. UA normalization and the fresh runtime fetch-options snapshot remain in the host fetch callback. The actual latest-row operation still calls the existing shared automatic-commit policy from inside the host state-store update, and `System.currentTimeMillis()` stays at that same update point. The execution helper does not move timestamp creation earlier or add deletion/eligibility/revision fences. A no-op commit for a removed row still returns Unit, followed by reconciliation and Success.

Seven tests have been drafted outside the source tree for this future production helper: missing/ineligible input without callbacks; captured-profile identity, trimmed URL, normalized document and ordered commit/reconcile; Error diagnostics; no-op commit still followed by reconcile; exceptions and cancellation at each of the three callbacks. They are not copied policy-lambda implementations. They have not yet run and prove neither WorkManager context/input guards nor Android UA/options integration; extraction wiring review and the retained adapter tests supplement the helper baseline. No new production implementation is authorized until root promotes/reviews the tests and captures missing-API RED.
