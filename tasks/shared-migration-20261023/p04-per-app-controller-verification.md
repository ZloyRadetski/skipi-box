# P04 — Per-App shared controller verification

23 October 2026. This verifies the shared controller operations and their Desktop profile-store adapter. **P04 remains open:** the Android/Desktop UI callbacks and a shared Per-App screen/state have not been connected. See [the Per-App source audit and remaining work](p04-remaining-per-app-research.md).

## Source contract and review

Android Per-App edits commit immediately to the profile selected by ID. Changing the mode keeps that profile's selected IDs; checking and unchecking apply every `selectionKey` from the row, retain unrelated and legacy IDs in order, and do not depend on the active profile. Clipboard import uses the existing Replace/Merge operation: an included mode is applied, a missing mode keeps the current mode, and Merge appends distinct entries. The source also reports the resulting selected-ID count for Replace and the non-negative size delta for Merge. These behaviors are captured in [the Android Per-App source audit](p04-remaining-per-app-research.md) and the Android callbacks in [`ProxyAppListPage.kt`](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt).

The shared `TrafficConfigEditorController` now exposes `setProxyAppListMode`, `setProxyAppListSelection`, and `applyProxyAppListImport`, plus the result DTO `TrafficConfigProxyAppListImportResult` ([controller](../../shared/app/src/commonMain/kotlin/app/skipi/app/config/TrafficConfigEditorController.kt#L59)). The setters transform only the addressed profile through `TrafficConfigEditorProfileStore`. Selection delegates to the shared `updateProxyAppListSelection` helper. Import delegates to `applyProxyAppListClipboardImport`, calculates counts with the Android formula, and returns zero for any result other than `Saved`. The existing update error policy remains in force: absent profiles return `Missing`; store exceptions are rethrown when no handler is configured, or reported through the configured callback as `Failed`.

The Desktop adapter reads and transforms the latest stored row by ID, then updates that row while retaining its library selection, order, next-ID counter, and row timestamp ([store](../../desktopApp/src/main/kotlin/app/skipi/desktop/DesktopTrafficConfigEditorProfileStore.kt)). The review found no required controller or adapter changes. This was a read-only review; no builds or tests were run during it.

## Tests-first evidence

The seven common tests and two Desktop file-store tests were written before the controller API. Root corrected a Desktop test import against the existing features.config writer before the first compile; no production or behavior expectation changed. The final API RED failed compilation in two seconds because the controller methods and result DTO did not yet exist; zero tests executed. The first API RED attempt took 19 seconds and also exposed a generic assertion-typing issue in the new failure test. That test typing was corrected before production work, with its expected state and behavior unchanged. Evidence: [final API RED counts](../../outputs/p04-per-app-controller-api-red-reports-20261023/counts.json) and [initial API RED counts](../../outputs/p04-per-app-controller-initial-api-red-reports-20261023/counts.json).

The common tests cover mode updates against the latest profile, shared-UID check/uncheck with unknown IDs retained, Replace and Merge behavior, Merge count clamping, a missing profile, and a handled store failure after transform but before commit. The Desktop tests use a real temporary `configs.json`; they reload after immediate mode/selection updates and exercise Merge after a same-ID edit and sibling insertion have been persisted following controller construction. They assert selected profile, ordering, next ID, source/lock/timestamp, unrelated document sections, and the full sibling records. They do not promise round-trip preservation of malformed whitespace or duplicate raw entries.

The scoped GREEN gate completed in **29 seconds**: shared app Desktop **355/355**, shared app Android **347/347**, Android app **15/15**, and Desktop app **11/11**. Total: **728/728**, failures/errors/skips **0**. The Android app set includes the editor oracle (4), clipboard oracle (9), and selection oracle (2). The Desktop set includes the two new per-app profile-store cases. `assembleDebug` also passed; the APK was not installed. Evidence and source hashes are recorded in [GREEN counts](../../outputs/p04-per-app-controller-green-reports-20261023/counts.json). The common and Desktop test source hashes are unchanged between final API RED and GREEN.

## Scope limits

This checkpoint verifies shared controller semantics and the Desktop file-backed store only. Android `ProxyAppListPage` still performs its own state callbacks, and neither host is wired to the new controller methods. It does not verify a shared Per-App screen, the Desktop More → UI Edit → Per-App route, an installed-app inventory, OS clipboard reads/writes, Android user-space/icon enumeration, VPN enforcement, or physical-device interaction. Those remain separate P04/R03 work; this checkpoint does not close P04.
