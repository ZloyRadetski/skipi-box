## Android Per-App contract

Android Basics exposes a Per-App section and navigates with the selected profile ID to Route.ProxyAppList(config.id), in [TrafficConfigEditorPages.kt](../../app/src/main/kotlin/features/config/TrafficConfigEditorPages.kt#L108). The existing page lives only in app code at [ProxyAppListPage.kt](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L86); its state and list projection are in [ProxyAppListPageState.kt](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L39) and [ProxyAppListData.kt](../../app/src/main/kotlin/features/proxy/app/model/ProxyAppListData.kt#L19). shared/ui/config currently has no Per-App or proxy-app-list screen.

The portable profile fields already exist in TrafficConfigState: proxyAppListMode and proxyAppListSelectedApps ([TrafficConfigDocument.kt](../../shared/core/src/commonMain/kotlin/features/config/TrafficConfigDocument.kt#L39)). The numeric mode contract is 0 blacklist, 1 whitelist, 2 global ([SkipiConfigDocument.kt](../../shared/core/src/commonMain/kotlin/features/config/SkipiConfigDocument.kt#L54)). In the profile document these become per-app-mode = blacklist|whitelist|global and repeated per-app-package values. Parsing trims, removes blanks, and deduplicates selected IDs; writing keeps the repeated package entries in order after the same normalization ([TrafficConfigDocument.kt](../../shared/core/src/commonMain/kotlin/features/config/TrafficConfigDocument.kt#L144), [writer](../../shared/core/src/commonMain/kotlin/features/config/TrafficConfigDocument.kt#L202)). Existing codec tests pin effective mode, repeated-value deduplication, legacy comment migration, and preservation of other SKIPI settings ([SkipiConfigDocumentTest.kt](../../shared/core/src/commonTest/kotlin/features/config/SkipiConfigDocumentTest.kt#L11)).

Unlike the Basics and detail forms, Per-App edits commit immediately. The page resolves the profile using trafficConfigId, not active-profile selection. A mode change transforms only that profile's proxyAppListMode and retains its selected IDs; checking an item transforms that same row's selected ID list immediately. There is no Per-App Save draft. Do not add a Save/Back draft or discard flow; Back only leaves after these already-committed changes. The source callbacks are at [ProxyAppListPage.kt](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L115) and [mode/selection writes](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L178).

The Android list model uses userId:packageName selection keys. A row carries selectionKeys, which can include every installed package with the same UID. Checking appends those keys and deduplicates; unchecking removes only those keys. Other stored IDs remain in their original order. The helper is [updateProxyAppListSelection](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L110); key construction and shared-UID grouping are in [ProxyAppListData.kt](../../app/src/main/kotlin/features/proxy/app/model/ProxyAppListData.kt#L253). Search trims its query and matches display name or package name case-insensitively ([ProxyAppListData.kt](../../app/src/main/kotlin/features/proxy/app/model/ProxyAppListData.kt#L189)).

Unknown and legacy IDs are intentionally retained when editing visible installed apps. The Android test keeps unprefixed configured package IDs while adding one installed ID and removing another ([ProxyAppListSelectionTest.kt](../../app/src/test/kotlin/features/proxy/app/ProxyAppListSelectionTest.kt#L13)). Do not clean these IDs during inventory refresh or add a free-text package-name editor: neither is Android behavior. The raw .conf editor already remains available for exact document edits.

There is also an existing portable way to edit the selected-ID set without an installed-app list. Android Per-App More includes Import from Clipboard and Export to Clipboard ([ProxyAppListComponents.kt](../../app/src/main/kotlin/features/proxy/app/ProxyAppListComponents.kt#L99)); the pure codec and Replace/Merge operation are currently app-only in [ProxyAppListClipboardCodec.kt](../../app/src/main/kotlin/features/proxy/app/usecase/ProxyAppListClipboardCodec.kt#L14). Export writes mode=... followed by package IDs. Import accepts explicit userId:packageName keys and bare package names; bare names are prefixed with the currentUserId input. It filters the host's selfPackageName, rejects malformed IDs, and uses the existing Replace/Merge confirmation. Imported mode replaces the current mode when supplied; without a mode header, current mode is retained. This is source behavior and can be shared without inventing a text editor.

The Android caller passes selectedUserId ?: 0 and LocalContext's application package to the pure decoder ([ProxyAppListPage.kt](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPage.kt#L194)). Preserve those as explicit host inputs when extracting the codec. A Desktop host has no Android user-space catalog or Android package identity: it must not fabricate installed app rows, icons, or a claim about its current Android user. It can retain the exact source fallback value 0 for bare package names when no selected user exists, solely as the existing serialization fallback; this does not assert that Desktop represents Android user 0. Keep selfPackageName an explicit host input rather than filtering an invented Android identity. Where the desktop has no inventory, selection-list rows are unavailable, but existing profile IDs and mode remain readable and persistable, and the existing clipboard import/export flow remains the source-backed selected-ID editing path. A real package provider, when available on a host, supplies actual rows to the common selection UI.

Enumeration, labels/icons, user-space discovery, Android self-package identity, and VPN policy application are host responsibilities. Android obtains inventory through AndroidPackageProvider and AndroidUserSpaceProvider in [ProxyAppListPageState.kt](../../app/src/main/kotlin/features/proxy/app/ProxyAppListPageState.kt#L68), while the VPN service applies whitelist/blacklist/global enforcement in [SkipiVpnService.kt](../../app/src/main/kotlin/engine/vpn/SkipiVpnService.kt#L419). Desktop should expose the common portable editor and store the data; it must not invent installed-app enumeration or claim to enforce per-app VPN policy.

## Scope distinction

The concrete P04 blocker is a missing shared Per-App editor/state boundary and Desktop connection, not the absence of a Desktop PackageManager. The current fields and document codec are already portable, and the Android page defines immediate-commit, selection, and clipboard-import behavior. A common screen can consume host-supplied app rows where available, while Desktop continues to edit mode and selected IDs through the existing clipboard flow without inventing installed apps. Full package list projection and OS integration stay in the dependent R03 work.
