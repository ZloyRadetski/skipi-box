# S03: source checkpoint перед завершением карточки

> Итоговое обновление 24 октября: S03 завершена; [приёмка](s03-acceptance-verification.md), [точка продолжения на R03](s03-handoff.md). Ниже сохранён исходный audit checkpoint.

Пользователь возобновил работу после R01 и выбрал порядок **S03 → R03**. Исходный checkpoint — `3d87f1c`. S03 остаётся открытой до интегрированных проверок; наличие уже общего кода не означает повторную реализацию.

Проверены три действующих пути:

- [Batch audit](../../outputs/drafts/s03-batch-source-audit.md): общий retained batch уже подключён к Android Home и Desktop. Сохраняем eligibility, изоляцию ошибок, per-ID lock, latest-state commit и отмену. Выявлен потерянный Android `Dispatchers.Default` вокруг load/import; [спецификация и тесты до production](../../outputs/drafts/s03-batch-dispatcher-spec.md). До исправления оба теста дали настоящий behavioral RED: fetch/options выполняются на caller-thread. Снимок XML/log/SHA — `outputs/s03-dispatcher-reports-20261023/red`.
- [Install audit](../../outputs/drafts/s03-install-source-audit.md): shared preparation, сохранение до fetch, disabled exact-URL duplicate и embedded-profile handoff уже существуют. Проверяем реальную последовательность host install и сохранённые параметры; Android notice для duplicate использует saved title. Manual Add имеет HTTP(S)-валидацию и в Android; расширять его custom-scheme UI по одному наличию parser callback нельзя.
- [Scheduling/worker audit](../../outputs/drafts/s03-scheduling-source-audit.md): общий Android work spec и worker outcomes уже извлечены. Desktop due-ID забирает только Proxy screen: на другой вкладке обновление не запускается. После ошибки неизменившийся lastUpdated может давать повтор через 1 секунду. Нужен app-lifetime host с тем же shared single refresh и source-backed periodic/backoff правилами, без зависимости от навигации. Отдельный P03 profile auto-update не дублируется.

WorkManager/таймер, факты сети/устройства, transport и системные уведомления остаются host adapters. Внутренние алгоритмы и переносимые решения должны быть общими. Android expiry alarms/notifier сохраняют существующие триггеры. Полное связывание expiry preferences/runtime отдельно указано в T02 (tasks/plan.md:533–537); отсутствие текущего Desktop notifier не является основанием исключать переносимый Android-сценарий. Этот срез S03 завершает batch/install/refresh periodic runtime, а не добавляет expiry UI/OS host попутно. Desktop OS protocol registration требует отдельного подтверждённого platform adapter; текущие существующие install entrypoints — ввод/clipboard. Не подменяем этой границей уже переносимые URI/parser/install операции.

Следующие срезы идут по правилу Android source → tests/RED или Android baseline → минимальная реализация → GREEN/review → commit. Запуски и новые итоги фиксируются отдельно; предыдущий полный R01 gate 2859/2859 — исходный baseline, а не проверка будущих S03 изменений. Посторонняя модификация native submodule сохраняется.
