# S03: Desktop single/batch/install/automatic wiring

Checkpoint started 23 October, continued after midnight 24 October 2026. Tests-first source/RED logs are preserved in `outputs/s03-single-operation-reports-20261023/red`, `outputs/s03-coordinator-reports-20261023/red`, and the earlier install/periodic reports. Missing operation/coordinator/classifier APIs failed at compile before production; these were not executed behavioral failures.

Desktop now has one single-refresh adapter using shared load/commit and the existing real latest-state persistence adapter. Load/import runs on Default; commit stays on caller. It returns the full receipt and server/profile change flags, including partial commit receipts. The retained batch uses that same load method. Typed HTTP statuses use the shared Android classifier; JDK HttpTimeoutException is supplied as a host connection fact, without inventing an HTTP status. Android retains its original classification.

One host coordinator serializes current Desktop manual, install, batch and automatic entrypoints. It re-reads the saved row after admission, and Main derives options from that row plus latest settings/current Core facts. Scheduled eligibility uses common worker policy; explicit install may refresh a disabled duplicate. Commit errors are permanent worker failures; load errors retain transient classification; stale/no-error receipt is success; cancellation propagates and releases admission.

The timer is now Main-level structured work, keyed by closeRequested. Targets reconcile/wake separately from navigation; old scheduledSubscriptionId/ProxyHome consumer is removed. Install awaits the common persistence + actual refresh before presenting its result, including saved duplicate title and real failure/partial-commit detail. Existing direct/client URI parsing is kept, and the existing Desktop clipboard path also accepts common SKIPI subscription links; no Desktop OS protocol/CLI registration is added here.

Initial focused Desktop gate: **151 cases, 149 passed and 2 failed**. Both failures were erroneous new test fixtures/oracles, diagnosed against existing source before correction:

- The canceled callback fixture assumed returning from withContext(NonCancellable) on the same dispatcher necessarily throws cancellation. The fixture now explicitly calls currentCoroutineContext().ensureActive() before intentionally suppressing the late cancellation; its expectations remain unchanged.
- The operation test demanded raw persisted profile byte equality. Existing common import deliberately adds a canonical [SKIPI] metadata envelope. The corrected oracle asserts exact source payload, exact parsed persisted Rule lines, profile source/name and activation; production was unchanged.

The two corrected suites then passed **9/9 GREEN**, six-second build. Other 142 initial cases were not repeated without a new cause. The existing real offscreen Compose Home/chain-member scenario passed in the initial gate; only obsolete callback props were removed from its fixture, without assertion changes. Original/final test hashes and all XML/log/counts are in `outputs/s03-desktop-reports-20261023/{initial,fixtures-green}`. This report explicitly does not claim all tests retained their original hash: these two source-backed fixture corrections are recorded.

Root and independent Luna reviewers found no further blocker in current load/commit, latest-state capture, progress, reconnect and app-lifetime wiring. **S03 remains open** for two final CONNECTED constraint races: network loss while waiting for admission must defer without false success; network loss during an active scheduled fetch must cancel its child and leave the schedule due. Both receive tests/RED before further production changes. The final full eight-target + real Core/build gate follows those corrections.
