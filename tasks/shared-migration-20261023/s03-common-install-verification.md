# S03: shared persist-before-refresh install

Source contract: Android first prepares the exact-URL duplicate/new row, persists it, then refreshes exactly that one group through existing load/apply operations. Disabled duplicates remain eligible for this explicit install refresh; bulk/worker eligibility stays separate. Saved duplicate fields and title win. A failed fetch leaves a new persisted row, and embedded profile handoff keeps Android activation semantics.

New Android baseline before production: `SubscriptionInstallFirstFetchTest` **2/2 GREEN** with local HTTP only and isolated Robolectric storage. The first actual request verifies stored UA, generated Age public-key header and device-header setting; timeout and inactive proxy facts are checked through the existing options mapper. A separate success carries non-activating embedded profile content and preserves the active profile. No real Core proxy or device data is used. A test-fixture correction selected the installed URL rather than assuming no stock built-in group; it happened before this baseline/production extraction, with no changed product expectations.

New common app/UI tests were run before production and gave **compile/API RED** for absent `installAndRefresh` and `formatSubscriptionInstallMessage`. Desktop install/clipboard API RED is preserved separately. The first incidental Desktop compilation also had unresolved-type inference cascades; these were not runtime failures or proof of a product regression.

Minimal common implementation now owns the awaited `repository.updateCatalog` followed by exactly one real host refresh callback and returns the full preparation plus callback result. Refresh failure does not roll back persisted preparation. Android delegates to it using the same updateSubscriptions + applyProxySubscriptionUpdates path and the same current saved-group lookup; its duplicate message helper delegates to a shared saved-title formatter.

Combined shared/Android focused gate after production: **218/218 GREEN**, 30s, failures/errors/skips zero: core Desktop11/Android8, app68/68, UI6/6, Android51 (including install, workers, retained refresh and apply/cancellation parity). Frozen test hashes match source-provenance.json. XML/log/counts under `outputs/s03-common-install-periodic-reports-20261023/green`; preproduction install evidence under `outputs/s03-install-reports-20261023/baseline-red`.

This checkpoint accepts common/Android install. Desktop clipboard parser, single-operation host, periodic timer and Main wiring are still being integrated under their own tests-first gates; this report does not close S03 or claim Desktop UI end-to-end verification.
