# R02 resource policy and snapshot-store checkpoint — 18 October 2026

This checkpoint records the resource-kind and activation/restore policy, the shared JVM profile snapshot store with Android wiring, and the real Desktop file-store adapter. It does not complete the R02 catalog, queue, or host integration. The Desktop adapter performs real file I/O, but Desktop UI, runtime resource assets/sources/downloads, and Core startup are not wired to it. R02, P04, and R01 remain open.

The policy baseline and implementation are commits `3a4c008` and `0a59c7d`. The corrected Android snapshot oracle is `58313de`. Shared snapshot-store and Android wiring are in `1c60e6d`; the Desktop adapter is in `58f240d`. Final evidence is at `a3e0a12`. The prior 2,253-test P04/R01 run is superseded as the latest full regression by the R02 final run below.

## Behavior preserved

The policy source is the Android implementation at `2f72cc9`. Profile activation remains `isProfileScoped && storedSource != requestedSource`; a missing profile marker activates the requested source, equal markers do not, and the legacy unscoped directory does not activate on a source mismatch. A missing or empty file is eligible for restoration before Custom protection. A nonempty Custom resource file is protected during package-update restoration; `XrayCore` retains its policy exception, while the ordinary bundled-resource loop still skips Core. Package restoration requires a positive bundled timestamp strictly newer than the target.

The common `ResourceFileKind` preserves Android's six entries, order, filenames, and display names. The Android `app.ResourceFileKind` typealias preserves Kotlin source imports, and the store uses the shared type and policy directly. The shared snapshot store owns profile paths and snapshots; Android retains its OS-specific atomic rename and asset access. The Desktop adapter writes to a same-directory temporary file and atomically replaces the target. The final source review restored Android's cleanup boundary for an input open/read failure and restored fresh file-existence checks in status creation. These fixes preserved the observed partial-write behavior and did not change test assertions.

Bundled restore, decompression, and legacy migration remain the next R02 slice. The approved test contract preserves Android's per-file partial restores and missing-asset behavior: failures are reported immediately, later files are still attempted, successful files are not rolled back, and the source marker is committed only when all attempted restores succeed. Desktop will package the existing canonical Android `geo/**` and `xray/**` assets at the same relative paths; no missing asset content or default provider files will be invented.
