## Scope under test

The active slice connects a Desktop selected stored row to the common Android-derived outbound plan and local Xray JSON composer when no `.conf` profile is active. The selected row is decoded before any server-list mapping so that an invalid first row with a duplicate ID remains a failure. An active profile continues through `DesktopTrafficProfileXrayConfigFactory`; selected raw `Custom` remains on `buildDesktopCustomXrayConfig`.

The Desktop adapter inputs are the selected server library, current traffic-config contents, local listener options, current subscription probe URL, and a snapshot of Desktop latency results. Persisted `subscriptionId == null` maps to the existing manual group ID `1`; `-2` remains the Auto group ID. Automatic group fallback uses that captured latency snapshot and the current subscription probe URL when the strategy probe URL is blank. Main preview and runtime start plans call the shared Desktop entry point. Full JSON export captures the server library, config library, listener options, traffic-config map, subscription probe URL, and a copied latency map before `withContext(Dispatchers.IO)`, then builds a temporary library containing the edited selected server and calls the same entry point. The Full JSON capture sequence was checked in Main source, not in a direct UI test; runtime start/retry snapshot behavior was source-reviewed and covered by existing lifecycle tests.

## Source corrections and behavior boundaries

- The common planner's config-owned `StrategyGroup` resolves members from the referenced `.conf`, but its probe URL and interval come from the model. Android's `ShadowrocketPolicyGroup.toEditableStrategyGroup` populates those model fields from the parsed group, and Android's `reconcileConfigProxyGroups` does the same. Therefore the fixture sets `probeUrl` and `probeInterval` explicitly instead of expecting the planner to reparse those values while resolving membership. See [ShadowrocketStrategyGroup.kt](../../shared/core/src/commonMain/kotlin/features/config/ShadowrocketStrategyGroup.kt#L56) and [ConfigProxyGroupReconciler.kt](../../shared/app/src/commonMain/kotlin/app/skipi/app/proxy/ConfigProxyGroupReconciler.kt#L95).
- A selected automatic group is a balancer target. `planXrayRouting` assigns `DEFAULT_ROUTE_LOOPBACK` as the primary outbound for a balancer and prepends a loopback-in route to the balancer; the final route still targets the balancer for TCP/UDP. The output order is loopback, policy-member outbounds, direct, and block. The Desktop fixture was corrected to that Android-derived shape; it does not expect a synthetic `proxy` outbound. See [XrayRoutingPlan.kt](../../shared/core/src/commonMain/kotlin/engine/xray/XrayRoutingPlan.kt#L61) and [XrayOutboundRenderer.kt](../../shared/core/src/commonMain/kotlin/engine/xray/XrayOutboundRenderer.kt#L42).
- The active-profile entry-point assertion expects Android's existing normalized domain rule, `full:only-in-conf.example`; `ShadowrocketRouteRuleConversion` prefixes `DOMAIN` values with `full:`. This corrects the test expectation only; the active-profile dispatch and converter remain unchanged. See [ShadowrocketRouteRuleConversion.kt](../../shared/core/src/commonMain/kotlin/features/config/ShadowrocketRouteRuleConversion.kt#L21).
- SOCKS model outbounds put the endpoint under `settings.address` and `settings.port`, which is the correct JSON path for the selected-chain assertions. See [Socks.kt](../../shared/core/src/commonMain/kotlin/features/proxy/server/model/Socks.kt#L28).
- Desktop's legacy local builder would serialize `OlcRtc` as a SOCKS outbound to its preferred localhost port, although Desktop has no OLCRTC start/readiness bridge. `AmneziaWg.toXrayOutbound` serializes WireGuard settings, while the native Amnezia runner is wired through Android's `SkipiCoreRuntime`. The Desktop `DesktopCoreController` owns only the FFM Core session and exposes no matching bridge API. To meet X03's explicit unsupported-native boundary without inventing a localhost endpoint, the selected-server adapter tests require a failure identifying the missing bridge/runtime for direct OLCRTC/AWG selection and for native members inside a selected chain/strategy group. Fixtures assert `validateFull().isEmpty()` so invalid fields cannot explain the intended failure. These focused behavior assertions are GREEN. The Core integration cases use an existing configured runtime; native artifacts were not rebuilt.
