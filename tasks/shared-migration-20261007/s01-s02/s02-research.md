# S02 refresh contract research

Source audit for the approved single-subscription refresh migration, based on HEAD `4202f31`. This note records Android behavior as the contract; the Desktop path is comparison evidence only. The common engine/test-first slice was later authorized after the root agent captured API RED. This agent did not run Gradle; the root agent owns serialized Gradle runs.

## Scope from the current plan

`tasks/plan.md:271-285` assigns S02 one refreshed subscription at a time. Shared code owns load/validate/rebase/commit ordering, subscription identity, server reconciliation, and metadata. Network fetch remains a port. Acceptance explicitly includes empty/partial responses, ID/latency matching, override and metadata, current identity and catalog behavior when the target changes or is deleted, cancellation, and partial repository failure. A linked profile is only a compatible handoff at this stage; full profile integration waits on P02/P03 (`tasks/plan.md:81`, `399-413`).

## Android one-subscription behavior

### Request and load

- `app/src/main/kotlin/features/subscription/usecase/SubscriptionUpdateUseCase.kt:32-84` wraps the single-group function in the existing shared batch loader. The group is locked through a process-local `SubscriptionUpdateCoordinator` keyed by group ID (`:155-163`). The single UI path passes a snapshot of the group; fetch options are built from the latest app settings at loader invocation.
- Per-group options are `useRunningProxy = group.updateViaProxy && proxyRunning`, that group’s `ageSecretKey`, global `enableSubscriptionDeviceHeaders`, and global `subscriptionFetchTimeoutSeconds` (`SubscriptionUpdateUseCase.kt:179-185`). Android defaults are device headers on and 10-second timeout (`app/src/main/kotlin/app/AppState.kt:135-140`). The group `hwid` field is not used by this request path; request device identity comes from the installation HWID owned by `AndroidSubscriptionFetcher`.
- A direct/manual one-group refresh does not reject a disabled group or blank URL before calling the updater (`SubscriptionGroupListPage.kt:145-164`, `ProxyServerListPage.kt:361-370`); the request then naturally fails if the URL is invalid/blank. Batch callers filter to enabled, nonblank groups, and the worker skips disabled/blank groups (`ProxyServerUseCases.kt:312-316`, `SubscriptionWorkerRunner.kt:20-24`). Do not move batch/worker eligibility rules into the single manual operation.
- The fetcher returns `SubscriptionFetchResponse` after HTTP handling and Age decryption (`app/src/main/kotlin/features/subscription/runtime/AndroidSubscriptionFetcher.kt:41-74, 109-164, 166-203`). A nonblank trimmed secret is converted to a public key before the request and sent as `X-Age-Public-Key`; a response body beginning with the Age armor header is decrypted and requires that secret, while other content passes through (`:166-203`). A root response supplies both body and headers; provider and embedded-URL fetches reuse the same group user agent/options and consume body only (`SubscriptionUpdateUseCase.kt:91-120`). The shared parser is called with `ProxyServerImportSource.SubscriptionUrl`, whose contract allows Base64 decoding; nested provider fetches come through the same callback (`SubscriptionUpdateUseCase.kt:94-100`, `app/src/main/kotlin/features/proxy/server/usecase/ProxyServerImportUseCase.kt:10-20`, `shared/core/src/commonMain/kotlin/features/proxy/server/usecase/ProxyServerImportContract.kt:15-24`).
- Response metadata comes from the root `SubscriptionFetchResponse` (`SubscriptionUpdateUseCase.kt:101`); nested provider response headers are not merged into it. Embedded traffic-config content is decoded inline or fetched using the same fetch options. Failure to load the optional embedded content is swallowed except for coroutine cancellation (`:102-121`).
- The response is a successful update only when `importResult.servers` is nonempty (`:123-141`). Zero usable servers raises the existing “Subscription update imported no proxy servers” failure and produces no refresh update to commit. A partial import with one or more usable servers is retained as-is with the parsed URL count and metadata; there is no all-entries-must-parse condition. Nested provider failures can therefore coexist with a nonempty server result.

### Freshness and target identity

- Android stores request identity as `SubscriptionGroupFetchIdentity(url, userAgent, updateInterval, ageSecretKey, updateViaProxy, enabled)` (`app/src/main/kotlin/features/proxy/server/usecase/ProxyServerUseCases.kt:35-61`). The group ID is also compared separately. This exact projection is important: comparing the whole subscription record would reject changes Android currently accepts.
- At commit, the update is applicable only if a current group with the same ID still has the captured identity (`ProxyServerUseCases.kt:140-150, 237-248`). A deleted group or a change to any identity member is silently ignored, with no server or metadata change. Deleting and recreating the same ID with exactly the same identity is accepted because Android has no generation/tombstone token. Current Android result/message accounting is based on successful loads, so a result ignored at commit may still count as an update in the UI (`SubscriptionUpdateUseCase.kt:77-83, 188-211`).
- Group title/name, `autoOverrideRules`, `hwid`, built-in status, expiry settings, and metadata are not part of this identity projection. `autoOverrideRules` is read from the current group when applying the response (`ProxyServerUseCases.kt:153-168, 245-265`). Therefore a title/override-only edit during fetch does not reject the response, and the latest override value is applied. Do not turn Desktop’s full-record conflict into the shared policy.
- Android does not capture or compare the existing target server-group snapshot. It applies a valid refresh against the latest proxy catalog; a concurrent edit to that same subscription’s server rows can be replaced. Unrelated catalog changes are rebased and retained. This differs from Desktop’s existing target-server conflict/suppression behavior.

### Reconciliation and metadata

- `shared/app/src/commonMain/kotlin/app/skipi/app/proxy/SubscriptionServerCollectionReconciler.kt:26-73` calls the shared core `reconcileSubscriptionServers` with default Android-compatible policy: fingerprint match first, then endpoint, then same-type position; no incoming deduplication. IDs are retained for matches. Android converts matched records back with their prior latency (`:44-73`; `app/src/main/kotlin/data/repository/AndroidProxyServerRepository.kt:67-91` also preserves latency by record ID).
- Newly imported `Custom` servers receive current `autoOverrideRules` as `overrideInboundAndDns`; other types are unchanged (`SubscriptionServerCollectionReconciler.kt:58-72`). Old target rows are replaced; non-target non-composite rows remain. Strategy and chain references are remapped through `oldIdToNewId`, invalid references are filtered per existing rules, and selection remains if its ID survives or falls back to a surviving server (`:74-127`). The resulting order is refreshed rows, other rows, then composites.
- Metadata merges onto current stored metadata via `SubscriptionRecord.withRefreshedMetadata` (`shared/app/src/commonMain/kotlin/app/skipi/app/subscription/SubscriptionMetadataRefresh.kt:10-35`). Response fields that are absent retain their previous value; title changes only for a nonblank response `profileTitle`; `lastUpdatedAtMillis` is set to the refresh timestamp. Traffic counters replace previous values only when `userInfoReceived` is true, while the metadata `userInfoReceived` flag itself reflects the latest response.
- On Android, group mapping persists title, profile title, announce/support/web/announce URL, interval, traffic counters, and last-update time (`ProxyServerUseCases.kt:173-209`). `SubscriptionGroupState` has no description or embedded-config storage fields (`app/src/main/kotlin/app/AppStateModels.kt:44-69`), so those `SubscriptionMetadata` values are not round-tripped into that Android model; the linked config is handled separately. Existing storage fields must not be invented to paper over this.

### Commit ordering, rebasing, and errors

- `applyProxySubscriptionUpdates` first invokes `proxyServerRepository.updateCatalog` with the current catalog and current groups, then applies updated groups/metadata to `AppState`; config-derived proxy groups are reconciled afterward if profile state changed (`app/src/main/kotlin/features/proxy/server/usecase/ProxyServerUseCases.kt:280-310`). Android’s repository delegates catalog mutation to `AndroidAppStateStore.update` (`app/src/main/kotlin/data/repository/AndroidProxyServerRepository.kt:54-58`); that mutates the current in-memory state synchronously and schedules Room/SharedPreferences persistence asynchronously. Persistence failures are logged and retried after database reset rather than returned to the refresh caller (`app/src/main/kotlin/data/AndroidAppStateStore.kt:74-97, 157-193`). Thus Android has no observable cross-store save error/rollback for these writes: both catalog and metadata are in the same application state, in the logical order catalog then group metadata.
- Desktop’s current path is different: it saves/publishes the subscription library first, then updates/saves the server library, then optionally saves the embedded profile (`desktopApp/src/main/kotlin/app/skipi/desktop/Main.kt:1083-1118, 1130-1172`). A server-save failure leaves metadata committed; a later profile-save failure leaves subscription and servers committed. This is not the Android order and should not define shared semantics. The planned shared ports do not imply a global transaction (`tasks/plan.md` preservation rules and S02 lines 279-283).
- The common refresh reducer operates on one host-supplied latest aggregate: complete `SubscriptionRecord`s plus latency-bearing collection rows, next-server ID, and selected-server ID. It validates the source identity, runs the existing shared collection reconciler using the latest `autoOverrideRules`, and patches metadata on the latest full subscription record. It does no repository I/O and does not impose a cross-store write order.
- Android captures/applies that aggregate through its existing AppState update path, where catalog and group metadata remain one logical application-state update. Desktop keeps its existing ordered subscription/server/profile persistence adapters and maps opaque server-library rows around the portable reducer. A save failure can therefore leave earlier Desktop writes committed; no global cross-repository transaction is claimed. The profile payload is returned only for an applicable identity, for the host’s existing integration boundary.
- Cancellation is rethrown by Android’s per-group updater and the shared batch loader (`SubscriptionUpdateUseCase.kt:143-151`, `shared/app/src/commonMain/kotlin/app/skipi/app/subscription/SubscriptionRefreshUseCase.kt:47-70`). Cancellation during optional embedded-config fetch also propagates (`SubscriptionUpdateUseCase.kt:102-110`). Ordinary fetch/parse failures become per-group `Result.failure`; there are no writes for that group. S02’s one-operation path should keep cancellation out of an ordinary refresh failure result.

## Consumers and current shared/Desktop code

- Android Home single refresh routes through `ProxyHomeEffect.RefreshSubscription` to `ProxyServerListPage.updateSubscription` (`app/src/main/kotlin/features/proxy/server/list/ProxyServerListPage.kt:743-747, 361-390`). The subscription-group screen’s `onUpdate` routes to `SubscriptionGroupListPage.updateSubscriptionGroup` (`app/src/main/kotlin/features/subscription/SubscriptionGroupListPage.kt:115-124, 145-183`). Both call `updateSubscriptions` and `applyProxySubscriptionUpdates`.
- Android background scheduling observes subscription identity/interval and schedules WorkManager (`app/src/main/kotlin/app/SkipiApplication.kt:85-101`); `SubscriptionWorker.updateSubscription` uses the same lower-level updater and commit (`app/src/main/kotlin/features/subscription/runtime/SubscriptionWorker.kt:34-59`). `SubscriptionWorkerRunner` skips absent/disabled/blank-URL groups and selects retry/failure from returned failures (`app/src/main/kotlin/features/subscription/runtime/SubscriptionWorkerRunner.kt:16-31`). Mass refresh is separately called from the Home/list actions (`ProxyServerListPage.kt:393-432`, `ProxyServerListActions.kt:432-468`) and is S03 consumer work, not permission to take S03 here.
- Deeplink/install handling reaches `SubscriptionInstallConfigUseCase.install`, which prepares an install group then uses the same one-group updater (`app/src/main/kotlin/features/subscription/SubscriptionInstallConfigUseCase.kt:31-55, 75-89`). Install grouping and URI behavior belong to S03; S02 research only records its dependency on the single-refresh operation.
- Shared `SubscriptionRefreshUseCase.kt:10-33, 47-71` still provides generic loader/snapshot and batch helpers. The typed single-refresh path is now in `SubscriptionRefreshOperation.kt`: common load/import/embedded resolution and a pure reducer over the latest aggregate. Existing generic `subscriptionRefreshConflict` (`SubscriptionRefreshUseCase.kt:73-100`) includes full-value target equality and embedded-profile conflicts; those remain inapplicable to S02 Android semantics.
- Shared reconciliation already exists in `SubscriptionServerCollectionReconciler.kt`, and shared repository ports exist in `RepositoryContracts.kt:24-62`: `ProxyServerRepository.updateCatalog` can rebase against the current catalog; `SubscriptionRepository` exposes the current records and `upsert`. `SubscriptionRepository.refresh` currently returns only a `SubscriptionRecord` and adapter refresh callbacks are unsupported/unwired on Android by default (`AndroidAppRepositories.kt:47-60, 103-174`; Desktop’s callback defaults to failure at `DesktopApplicationRepositories.kt:152-163`). The shared application action currently delegates only to that repository callback (`SharedApplicationStore.kt:65-68, 225-228`), so it is not the existing full refresh operation.
- Desktop `Main.kt:936-1179` calls `runSubscriptionRefresh`, but the shared helper only wraps caller-owned capture/load/commit. Desktop fetches/imports in its adapter, snapshots by URL and target server/config libraries, and uses `DesktopSubscriptionRefreshCommitter` (`desktopApp/src/main/kotlin/app/skipi/desktop/DesktopSubscriptionRefreshCommit.kt:19-98`). It conflicts on any changed full subscription snapshot, suppresses replacing a target server group edited during load, and separately rejects changed/locked embedded profiles (`:55-61, 77-98, 120-130`). Those are Desktop-specific policies, not Android’s source contract for S02.

## Common S02 engine contract and first test slice

The common load API receives a full S01 `SubscriptionRecord` and an opaque host options value. Its response callback receives root, nested-provider, and embedded-URL requests together with the same subscription user agent and same opaque options. The host remains responsible for HTTP behavior, device headers, proxy selection, timeout, Age request/decryption, and platform/runtime setup. Shared code owns `SubscriptionUrl` import order, provider fetch callback wiring, root-response metadata parsing, inline/remote embedded-config resolution, empty-server validation, and a cancellation guard after parsers that may catch callback exceptions.

The loaded result carries the Android identity projection (ID, URL, user agent, update interval, Age secret, update-via-proxy, enabled), parsed URL count and servers, root `SubscriptionMetadata`, and an optional `ResolvedEmbeddedSubscriptionConfig` handoff. Embedded URL errors are best-effort except `CancellationException`; inline content is decoded with `decodeSkipiPayload()` or trimmed. Android’s exact `subscription://<id>` inline source, remote URL source, blank-name fallback, and activate bit are returned. Embedded resolution occurs before empty-server validation, matching Android.

`reconcileSubscriptionRefresh(snapshot, loaded, refreshedAtMillis)` uses `loaded.sourceIdentity` as the only authoritative request identity. It reads the latest complete subscription, silently returns the aggregate unchanged if the group is missing or any identity field changed, and withholds the profile handoff on that stale result. Otherwise it reconciles latency-bearing collection rows through `reconcileSubscriptionServerCollection`, preserving matched IDs/latency, unrelated rows, composite references, current selection/high-water behavior, and applying latest `autoOverrideRules`. It patches response metadata on the latest full subscription record via `withRefreshedMetadata`; an interval explicitly supplied by this response updates the direct record option, while an omitted interval retains prior metadata and the current direct option. Non-identity edits remain current. Shared code does not compare target-row snapshots, add generation checks, or impose host persistence ordering.

The first common test slice is in `shared/app/src/commonTest/kotlin/app/skipi/app/subscription/SubscriptionRefreshOperationTest.kt`. It covers exact identity fields; latest-state reconciliation with ID/latency, unrelated rows, composite references, high-water/selection, latest override, sparse metadata and update interval; stale/deleted no-op and no stale handoff; root/provider/embedded calls reusing options; exact embedded source/name/activation; best-effort error vs cancellation; explicit provider cancellation fallback while its caller remains active; caller-job cancellation during parser fallback; and embedded resolution before empty-import failure. The root agent owns the recorded API RED and all Gradle runs. Android/Desktop adapter wiring and repository save-order tests remain later host-integration work, with no global cross-store transaction assumption.

Request options with Android defaults remain host facts/adapters, not shared defaults. P01 is done; P02/P03 remain open. This slice only hands resolved linked-config content back to the host; it does not implement profile lifecycle, conflict/lock policy, or linked-group integration.

## Profile boundary

P01 is done; P02 and P03 remain unchecked in `tasks/todo.md:33-35`. S02 now returns the resolved inline/remote config as `ResolvedEmbeddedSubscriptionConfig`; the host passes that handoff to its existing profile integration. This does not claim shared profile lifecycle/update-lock/selection integration. P02 owns common profile lifecycle, and P03 owns refresh/linked groups. Desktop’s newer optimistic profile checks are not the Android rule.
