# R02 ordered resource-update plan — 19 October 2026

This checkpoint records the tests-first move of Android's ordered resource-update planning into `shared/core`. It is a focused slice only: the Desktop downloader runner and resource UI are still outstanding, and the broader R02, P04, and R01 cards remain open. Production and tests are in `5fa1c38`; evidence is in `d2bdedc`. The Android plan behavior baseline is `be1378d`, and the separate downloader behavior baseline is `4e5b13c`.

## Behavior preserved

The Android source oracle is `be1378d`. Full updates keep the five updateable built-ins in the existing order—GeoIP, GeoSite, GeoIP-only-CN-private, direct IPv4 CIDR, direct IPv6 CIDR—then include eligible custom entries in profile-list order. Xray Core remains excluded from full URL updates; an explicit single-kind Xray Core request still throws the same display-name-based `IllegalStateException` before downloads begin.

Built-in URLs remain byte-for-byte as supplied by the resolved source, including whitespace. Custom URLs are trimmed and skipped when blank. A custom target basename is sanitized using the existing shared filename sanitizer and falls back to `custom-resource-<id>.dat`; all six reserved resource filenames are skipped after sanitization. Custom entries preserve their original `TrafficConfigCustomResourceFile` metadata, and duplicate IDs or basenames are not deduplicated. The scope retains its raw `resourceFileSource` value, including an invalid provider index; planning does not replace it with a resolved source ID.

`AndroidResourceFileRepository` adapts each accepted plan entry into the existing download target, then continues through the existing serial download, progress notification, permissions, status, source-marker, completion/failure notification, and cancellation path. A full update marks the captured scope's source only after all downloads and status collection succeed; single built-in and custom updates do not mark it. Empty plans return current status without starting the download/notification pipeline. Reserved-name filtering now happens in the shared plan, after the queue has captured its request targets; it is not part of global queue deduplication. Source review against `be1378d` found no behavior mismatch. The `ResourceSnapshotFiles.file(customFile)` change delegates to the same sanitizer and fallback through the shared `resourceFileName` helper.
