# R02 common resource-source resolver — 19 October 2026

This checkpoint records the common provider catalog and source-resolution slice. It moves only source selection and URL fallback rules; download coordination, network access, resource-file writes, and Desktop resource UI remain outside this slice. Production is commit `0e2978d`; evidence is commit `d14f303`.

## Android behavior preserved

The common catalog keeps the Android preset order and IDs: `0` Loyalsoldier, `1` V2Fly, `2` Chocolate4U, `3` RunetFreedom, and `4` Roscomvpn. Each preset retains its original GeoIP and GeoSite endpoints. All five reuse V2Fly's CN-private GeoIP URL and the same direct-CIDR IPv4/IPv6 URLs. The source-specific URLs and common endpoints are recorded in the [shared defaults](../../shared/core/src/commonMain/kotlin/features/resources/ResourceFileDefaults.kt#L20) and pinned literally in the Android and common tests.

Custom is source ID `5`. The index helper `resourceFileUpdateSourceAt(5)` still falls back to preset 0, as it did on Android; the source resolver treats `source == 5` as Custom and returns ID 5. It trims each custom URL independently, falling back per blank field to preset 0. Any invalid non-Custom ID also resolves to preset 0 in the DTO. The requested source value remains the value used by the resource scope; do not normalize the stored scope to the resolved DTO ID.

The Android-compatible `app.ResourceFileUpdateSource` alias, provider-list wrapper, and index helper remain available. `AppState.resourceFileUpdateSource()` continues to resolve from global `AppState` source/custom fields, even when the active traffic profile has different resource settings. The resource page's update request and displayed selection use the common extension on that selected profile's `TrafficConfigResourceSettings`, preserving profile-local source values. The implementation is in [ResourceFileUpdateSource.kt](../../shared/core/src/commonMain/kotlin/features/resources/ResourceFileUpdateSource.kt#L8), with Android compatibility forwarding in [AppStateModels.kt](../../app/src/main/kotlin/app/AppStateModels.kt#L72) and profile request wiring in [ResourceManagementPage.kt](../../app/src/main/kotlin/features/resources/ResourceManagementPage.kt#L164).

## Queue contract and next slice

The Android `ResourceFileUpdateCoordinator` baseline passed **8/8 GREEN** before any queue port (`9fa9a2b`). It remains the behavioral basis for the next slice. The eight cases pin serial FIFO execution; exact target deduplication across different profiles; rejection of an All request while anything is running or pending; the five built-in targets with Xray Core excluded; captured scope and copied custom-file list; failure and download-cancellation continuation; coroutine cancellation; and cancel-all behavior. All-request target construction includes custom files with nonblank URLs, while reserved-name custom entries are filtered downstream by the downloader. Preserve the global cross-profile target dedupe exactly; the profile-specific file store does not make duplicate queue targets profile-local. Evidence: [combined Android source and queue baseline log](../../outputs/r02-source-and-queue-android-baseline-green-20261019.log), [queue XML](../../outputs/r02-source-and-queue-android-baseline-20261019/TEST-features.resources.ResourceFileUpdateCoordinatorTest.xml), [coordinator test source](../../app/src/test/kotlin/features/resources/ResourceFileUpdateCoordinatorTest.kt#L24).
