# R02 shared resource-update queue — 19 October 2026

This checkpoint records the shared queue-model and queue-coordinator slice. Production is commit `0594ea2`; evidence is commit `136c843`. The queue model is in `shared/app` common code, and its synchronized coroutine coordinator is in `shared/app` JVM code, which is the dependency shared by Android and Desktop. Android continues to own its resource use case, downloader, and cancellation callback. The Desktop resource UI and download runner are not wired yet, so this slice does not complete R02, P04, or R01.

## Behavior carried from Android

The common request types capture the profile resource scope, selected source, update options, and a defensive copy of custom resource files. Update targets intentionally omit profile scope: a target already running or queued in one profile blocks the same target from another profile, preserving the prior global deduplication. Requests are processed FIFO and serially. Empty requests are rejected; an All request is rejected whenever any work is pending or running. All expands to the five updateable built-ins and custom entries with nonblank URLs, while excluding Xray Core.

The coordinator protects enqueue, dequeue, state publication, and completion bookkeeping with a JVM monitor. Its `StateFlow` publishes queue state; a `SharedFlow` with an extra buffer of 16 carries results. Completion increments the revision for Success, Failure, and a user-requested download cancellation. A coroutine `CancellationException` instead clears running and pending work and is rethrown without emitting a result or advancing the revision. `cancelAll()` clears pending work and calls the active host cancellation callback outside the monitor.

Android's existing `App` singleton now constructs the shared coordinator and maps its requests to the Android `ResourceFileUseCase`. The Android cancellation type remains as an alias to the shared download-cancellation exception, preserving the existing Android call boundary. Reserved-name custom files can be present in All's nonblank-URL target set; the actual reserved-name check remains in `AndroidResourceFileRepository`'s target builder (`toDownloadTargetOrNull`), downstream of queue construction.
